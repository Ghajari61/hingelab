# Decisions log

Decisions taken without the owner during the autopilot run. Each entry: what, why, alternatives.

## Run-wide

### D1. Commit locally, never push during the autopilot run
- **What:** every finished phase is committed on `main` locally. Nothing is pushed.
- **Why:** the GitHub repo `Ghajari61/hingelab` is connected to the Vercel project `hingelab`, so any push to `main` triggers a production deploy. The run rules forbid production deploys.
- **Alternatives:** push to a feature branch (Vercel would still build a public preview URL); disconnect the Vercel git integration (changes the owner's account settings).
- **Owner action:** see SETUP.md, "Publish the work".

### D2. Polygon library: keep `clipper-lib`, not `clipper2-js`
- **What:** all 2D boolean/offset work (Letters and Parametric) uses `clipper-lib` 6.4.2 through `lib/letters/polygon.ts` (1 unit = 0.001 mm).
- **Why:** during Letters L1, `clipper2-js` 1.2.4 `InflatePaths` produced wrong coordinates even for a 10×10 square inset by 1 mm. `clipper-lib` is the mature pure-JS port of Clipper 1 and is synchronous (no WASM init).
- **Alternatives:** `js-angusj-clipper` (WASM Clipper 1, async init, bundling issues in Next.js); patching `clipper2-js`.

### D3. Phase 1 of the main brief was already finished before this run
- **What:** the run starts by re-verifying Phase 1 (tests, type check) instead of rebuilding it.
- **Why:** Phase 1 (Hinge Box port, golden test, editor at `/app/editor/local`) and Letters L1 + L3 were completed and approved in earlier sessions. All 552 tests pass.

## Main brief

## Letters

### D21. Stencil bridges: where they go and what counts as a counter
- **What:** the text is welded into one outline, then each counter (hole) of each letter gets bridges. A bridge runs from a deep point inside the counter (pole of a 24 × 24 grid) along one of 16 rays to the outer edge of the stroke, choosing the shortest crossing that exits into the sheet (not into another counter). With 2 bridges per counter, the second must be at least 120° from the first. Each bridge is a rectangle `bridge width` wide, overshooting 0.3 mm on both ends so it overlaps cleanly.
- **Scrap threshold:** counters smaller than (2 × bridge width)² mm² are treated as scrap and left as holes. Fonts have tiny sliver counters (e.g. at the waist of Fredoka's "8") that cannot hold a bridge and would leave loose pixels.
- **Retry:** after cutting, the sheet must be a single piece. If more pieces remain (a bridge that did not fully sever a slanted stroke), every bridge is lengthened by one bridge width at both ends, up to 4 attempts; anything still loose produces a warning in Analysis instead of failing silently. The test also proves it independently by rasterising and flood-filling the sheet.
- **Bridge width default:** `max(2, material thickness)`, editable in the Stencil panel together with the sheet margin (default 20 mm).
- **Alternatives:** medial-axis bridges (more accurate but heavy for a browser), horizontal-only bridges like classic stencils (fail on rotated or Persian shapes).

### D22. Removed an obsolete test assertion
- **What:** `letters.test.ts` checked that `mode: "stencil"` returns "not available yet". L2 makes stencil available, so that assertion was removed; the test now checks only that empty text returns an error. This is a change of behaviour, not a weakened test: stencil is covered by the new test 9 (`stencil.test.ts`, 9 cases, including a raster flood-fill check that no part of the sheet is floating).

### D23. Marquee light holes follow the strokes
- **What:** hole centres lie in the region where a hole keeps `margin` clear of the wall's inner face (the outer wall face inset by T + margin + hole radius). Walking along that region's edges, a centre is kept when it is at least `spacing` from every kept centre. In a thin stroke the region is a sliver, so the bulbs run down the middle of the stroke; in a fat stroke they follow its outline. Spacing is never less than the hole diameter + 2 mm, so a web is always left between holes.
- **Where:** through the lid (and the lid lip of a removable lid, so light passes); through the base of an open tray. Hole paths run K/2 inside the nominal radius, like every other kerf-compensated cut.
- **Too small:** a letter with no room for a single hole gets a warning naming it.
- **Alternatives:** a hex grid clipped to the letter (misses thin strokes entirely), or a true medial axis (heavier, and the edge walk gives the same result on strokes).

### D24. Small pieces can be cut as stacks
- **What:** "Stack to full height" (off by default) cuts each flat small piece `round(depth / T)` times, named `… · dot k/n`, so the stack can be glued to stand as tall as the box. With "Leave out" it does nothing.
- **Why:** the brief asks for it; off by default because it multiplies the part count.

### D25. three.js preview: built in `lib`, rendered in a lazy client component
- **What:** `lib/letters/scene3d.ts` builds a `THREE.Group` with no renderer: plates by `ExtrudeGeometry` from the real cut shapes (light holes included), walls as T-thick bands along the wall centerlines with vertex colours (wood on flats, wood blended 55% with the bend verdict colour on curves), small pieces stacked on the lid. `LetterPreview3D` renders it with `OrbitControls`, only when something changes (no animation loop), and is loaded with `next/dynamic` so three.js is not in the editor's first bundle. Solid and Stencil show the flat parts T thick. A "Lift lid" slider separates the lid.
- **Not in `lib/letters/index.ts`:** the scene module is imported directly so server code that uses the letters library (export route) never pulls in three.js.
- **Alternatives:** the Hinge Box's hand-drawn SVG projection (cannot draw arbitrary letter shapes with holes), `@react-three/fiber` (a second dependency for one small view).

### D26. Analysis panel polish
- Each letter shows its tightest radius next to the hinge limit and its light-hole count; the box lists the longest strip or panel and the total light holes. Warnings ("To check") and notes are separate lists. Stencil counts are labelled as letter cut-outs and stencil bridges.

### D27. Letters on the Free plan, and where it is enforced
- **Rule:** Free users can use every Letters mode and setting with the live canvas and 3D preview. Export works only for a **Letter Box of one letter** (one visible character after removing spaces, counted as grapheme clusters so "é" or a Persian letter with marks is one), and carries the "Made with HingeLab" mark. Everything else opens "Upgrade to Pro". Solid and Stencil show a lock for Free users.
- **Server:** with accounts, Letters export goes through `POST /api/export` with `product: "letters"`. The server reads the plan, applies the rule (403 otherwise), builds the SVG itself with HarfBuzz and the bundled font from `public/fonts` (traced into the function via `outputFileTracingIncludes`; `harfbuzzjs` is a server-external package), and adds the mark. The output is byte-identical to the editor's own export (tested for Latin, Persian, box, solid and stencil).
- **Uploaded fonts:** the request carries the font as base64 (up to 3 MB, so the request stays under Vercel's 4.5 MB body limit). The server uses it for that one file and does not store it; the font picker note and the privacy page now say so. For a Pro user with a larger font, the editor exports locally (accepted: the same limitation as D15, the client already has the geometry); a Free user gets a message to use a smaller file.
- **Cloud save is not limited** for Letters (unlike Pro Hinge Box shapes, D14): the brief limits only export, and a new Letters project starts as "Sam" in Solid, so refusing saves would stop Free users from opening Letters in the cloud at all. Letters projects still count toward the 3-project limit.
- **Alternatives:** building the file in the browser and only stamping it on the server (bypassable), or refusing uploaded fonts on the server (Pro users would lose their own fonts).

## Parametric

### D28. Parametric P1: library shapes are generated, not downloaded
- **What:** the six library shapes (sphere, torus, wave panel, ripple, vase, and "abstract-head-cc0") are built by code in `lib/parametric/source/library.ts`. The head is a face relief over a 160 x 220 mm oval with a 3 mm flat back: a dome plus smooth bumps for brows, eye sockets, nose, cheeks, lips and chin. `public/library/LICENSES.md` records it as procedurally generated and released under CC0.
- **Why:** no network downloads during the run, no licence risk, tiny bundle, and the meshes are closed by construction.
- **Alternatives:** shipping a CC0 head scan (needs a vetted source and several MB).

### D29. Parametric P1: where each model sits relative to the wall
- **What:** imported meshes and the solid library shapes (sphere, torus, vase) are centred on the origin, as the brief says, so the wall plane z = 0 cuts them in half. The relief library shapes (head, wave panel, ripple) are centred in X and Y only and keep their flat back on z = 0.
- **Why:** the "sphere parallel" test expects half-discs from a centred sphere, while a relief centred in Z would lose half its depth behind the wall.
- **Alternatives:** centring everything (the head would be cut through the cheeks), or pushing everything to z >= 0 (breaks the sphere test).

### D30. Parametric P1: the wall cut is done per section in 2D
- **What:** instead of `trimByPlane` on the 3D solid, each section is intersected with the half-plane w >= 0 in Clipper.
- **Why:** it gives the same result for parallel fins (the section of the trimmed solid equals the trimmed section) and works the same way for the fallback sections of open meshes, which manifold cannot trim.

### D31. Parametric P1: section clean-up details
- **Pinned wall points:** Ramer-Douglas-Peucker and Chaikin keep every point on the wall line (w = 0) fixed and work on the runs between them. Otherwise RDP drops the corner where the profile meets the wall, which tilted the wall edge by up to 0.08 mm.
- **Opening (minimum feature):** erode by minFeature/2, grow back by minFeature/2 + 0.01 mm, then clip to the input, so straight edges come back exactly; Clipper's integer rounding otherwise left the wall edge 0.002 mm off.
- **Union rule:** nonzero for manifold sections (oriented), even-odd for fallback loops.
- **Fallback sections:** segment endpoints are joined on a 1e-4 mm grid; open chains shorter than 1 mm are dropped; longer ones are closed with a straight edge and reported as NON_MANIFOLD_SECTION.
- **Sphere test:** checks every fin vertex higher than minFeature/2 + 0.5 mm above the wall. The opening rounds the two corners where the disc meets the wall with radius minFeature/2, so those few vertices are not on the circle by design. The test also checks area (at least 97 % of the half-disc) and that the wall edge is exactly at 0.

### D32. Parametric P1: parts, short fins and floating pieces
- **Ids:** fins are F01..Fn by plane; a plane whose section has several pieces gives F07-a, F07-b, ... (largest first).
- **Short fins:** pieces lower than `minFinHeight` are left out and reported with a new warning code SHORT_FIN_DROPPED (the brief has no code for this).
- **Floating pieces:** P1 has no bridges (they come in P2), so pieces that do not touch the wall are kept as their own parts and reported with a new code FLOATING_PIECE, rather than misusing BRIDGE_ADDED.
- **Part-local frame:** x along the wall (U), y out of the wall (W); outers are counter-clockwise in that frame, which is our positive orientation. The placement matrix has columns U, W, N, offset x N.

### D33. Parametric P1: loading manifold-3d in the browser
- **What:** `scripts/copy-harfbuzz.js` became `scripts/copy-wasm.js` and also copies `manifold.js` and `manifold.wasm` to `public/manifold` (git-ignored). The slicing worker (`components/parametric/slicer.worker.ts`, a module worker) imports it with `webpackIgnore` and keeps the prepared mesh between runs.
- **Why:** same reason as HarfBuzz: the Emscripten module finds its .wasm next to itself, which webpack would rewrite.

### D34. Parametric P1: simplification and units
- Meshes over 300,000 triangles are simplified with meshoptimizer after normalising, so the reported error is in mm (target error 5 % of the diagonal as the cap; the triangle budget is the real target).
- Units "auto" with a diagonal outside 5-5000 sets `askUnits` in the worker result; the editor will show the one-line prompt in P2. GLB import is wired through `GLTFLoader.parseAsync` but has no automated test (building a GLB in Node needs browser APIs); STL and OBJ are tested.

### D35. Parametric P2: slat backboard
- **What:** "Slats" makes the backboard a plain rectangle (the plate outline's bounding box), and every fin row is extended across the whole board by a strip `slatDepth` mm high (new parameter, default 10 mm), so each row reads as one slat with the model's profile rising out of it. With "Fill the whole board with slats" on, planes outside the model become plain slats S01, S02, ... at the same spacing. `slatWidth` stays in the data model but is always T: slats are cut on edge from the sheet.
- **Why:** the brief names a slat mode but does not define it; this is the usual parametric-wall look and it reuses the fin, tab and slot code unchanged.
- **Alternatives:** separate horizontal slats on the board face (needs a second joint type), or slats as wide boards cut flat (thicker material than the fins).

### D36. Parametric P2: tabs, slots and the backboard
- Tabs are T wide in depth (tab depth defaults to the backboard thickness, which is T, since the board is cut from the same sheet), `tabWidth` long, about every 60 mm along each wall edge: two or more per edge, one when the edge is shorter than 2.5 tab widths, none when even one does not fit. Pieces without a tab get the new warning code NO_TAB and are listed for gluing in the assembly guide.
- Slots are drawn at nominal size (T + slot play) x (tab width + slot play); kerf is applied once, on the cut paths (outline +K/2, inner cuts -K/2), so a slot measures T + play - K after compensation. Tests check this on a 100 x 100 plate and in the exported SVG.
- The plate is the model's footprint on the wall (manifold `trimByPlane` + `project`; a staircase of the fins for open meshes) grown by the margin, plus a 4 mm border round every slot. Several separate footprints are joined by their convex hull so the board stays one part, B1.
- With backboard "None", fins get no tabs and no warning.

### D37. Parametric P2: island bridges
- A piece that does not touch the wall gets a vertical strip (width max(min feature, 4 mm)) from its lowest point straight down to the wall, clipped to the convex hull of the section plus the island's own shadow on the wall. Including the shadow means a section that floats entirely (for example a fin through the brim of a hat) still reaches the wall. Pieces a bridge cannot connect stay FLOATING_PIECE.

### D38. Parametric P2: labels and the engrave layer
- Labels are drawn with a small built-in single-stroke font (0-9, A-Z, "-", "." and space) at 4, 3 or 2.5 mm, whichever fits inside the part, with an arrow pointing to the wall edge. A label that fits at none of the sizes is skipped and counted under the new code LABEL_SKIPPED; the assembly guide still lists every part. The backboard is engraved with each fin id beside its first slot and "B1 TOP" with an arrow.
- Engrave paths go into the shared labels layer (C00, the Hinge Box labels colour) in the SVG, cut after the inner cuts and before the outline. "Score" style uses the same layer for now: the difference is a power setting in LightBurn.
- On the editor canvas engrave paths are drawn through the existing hairline channel of `Canvas` so no new layer type was needed.
- **Hidden face:** engraving is on the face the laser sees. For "auto-hidden-face" the label is placed near the wall edge, where the neighbouring fins hide it; true back-face engraving would need flipping parts on the sheet, which would mirror the outlines for the user.

### D39. Parametric P2: nesting v1
- Bounding-box MaxRects (best short side fit) over as many sheets as needed. Parts may turn 0 or 90 degrees, or to the angle that shrinks their box by more than 10 % (slim diagonal parts); grain "along width" allows only 0, "along height" only 90.
- Parts are packed in id order (so F01-F12 end up together) unless packing by size saves more than 5 % of the material. A part larger than the sheet goes alone on an oversize sheet marked in the SVG comment and on the canvas, with PART_TOO_BIG. More than 40 sheets adds TOO_MANY_SHEETS.
- **Alternatives:** true-shape nesting (better yield on fins with large empty areas); the API takes outlines and returns placements, so it can be swapped in later.

### D40. Parametric P2: formula sources
- Formulas are parsed with mathjs and compiled by walking the parse tree into closures over an allow-list (arithmetic, comparisons, the ternary, and sin ... clamp, noise2/noise3, smoothstep). Assignments, function definitions, property access, strings, matrices and unknown names are rejected with a message for the panel; nothing from mathjs runs when the formula is evaluated.
- A surface z = f(x, y) is sampled on the domain (centred on the origin) and lifted so its lowest point is `base` mm off the wall (default 5 mm), so negative values never cut into the backboard. The lift is reported to the test, which checks the fin tops follow 10 sin(x/20) + lift within chord tolerance + 0.05 mm.
- A turned shape r = f(h) is centred like the solid library shapes (D29).

### D41. Parametric P2: the editor
- Same shell as Hinge Box and Letters: menu bar, control bar (Method: Parallel fins; the other methods are shown as "soon"), tool rail, a centre area with "3D" and "Sheets" tabs, the dock, and the status bar. The "Export" button in the menu bar exports the ZIP; single sheets and the assembly guide are in the File menu and in Layers & Export.
- The worker re-slices 250 ms after the last change and the previous result stays on screen, with a progress strip under the tabs. Clicking a part in 3D, moving the Slice Inspector slider, or "Show" on a warning selects parts: they turn blue in 3D and get a blue outline on the sheets.
- Guest autosave key `hingelab-parametric-v1`. The imported model file is kept in IndexedDB (one model, the last imported); a saved project that points to a model this browser does not have falls back to the library head with a toast.
- Imported models whose size in "auto" units is implausible for millimetres show a one-line "It was made in mm / cm / m / inches" prompt in the Source panel (promised in D34).
- **Cloud projects:** Parametric is not saved to the cloud until P6, so choosing Parametric inside a cloud project opens the guest editor (`/app/editor/local`) with Parametric selected.

### D42. Parametric P2: export files
- One SVG per sheet (`sheet-01.svg` ...), width and height in mm, Inkscape layer groups in cut order slots (C03) then labels (C00) then outline (C02), each respecting the layer's export switch. The ZIP holds every sheet, `assembly-guide.svg` and `project.hingelab.json`; the imported mesh file is not included (it can be large and the user already has it).
- The assembly guide has an exploded isometric line drawing (drawn from the part placements, not a WebGL screenshot, so it also works on the server later), the backboard at full size with the part id in every slot, and numbered steps generated from the result (insertion order and direction, slats, parts to glue, fixing to the wall).

### D43. Parametric P3: stacked layers
- Layers are sections at the centre of every T-thick slab, from the bottom of the model: h_i = min + (i + 1/2)·T, as long as h_i is inside the model. Axis Y gives horizontal layers (a topographic model); axis Z gives layers parallel to the wall (a relief built up from the back). Layer ids L01...; when one layer falls apart into several pieces they are L07-a, L07-b, ... (largest first).
- **Dowels** are placed greedily from the bottom: a chain grows upward while the layers still share room for a dowel (every layer eroded by dowel radius + 2 mm, intersected). When the shared room runs out, the chain is closed and a new one starts (DOWEL_CHAIN_SPLIT). Positions inside a chain are spread as far apart as possible (up to `dowelCount`, at least 2·r + 4 mm apart), so they are concentric through every layer of the chain. Layers with no room at all are reported as NO_DOWEL (new code). Holes are cut at dowel Ø + slot play. Alternatives considered: one global dowel set (fails on any overhang) and a dowel per adjacent pair only (no alignment over the whole stack).
- **Registration marks:** the outline of the layer above is engraved on each layer, clipped 0.5 mm inside the piece (only the part of the next outline that actually lies on this layer).
- **Hollowing** removes only what the layers above and below both cover, offset inwards by the wall thickness `shell`, so no hole ever shows on the outside. A ring (dowel radius + 3 mm) is kept round every dowel and a spoke from each ring to the nearest outline, so no island comes loose. The first and last layer are never hollowed.
- **Labels** go on the covered (hidden) area of a layer first, where the next layer will hide them; then anywhere on the piece.

### D44. Parametric P3: waffle
- Two families of parallel planes along two of X/Y/Z (`familyAxes`, default X and Z: a standing egg-crate). Both families use the same frame rule: W runs along the common line, U = W × N, so a crossing is a vertical line x = const in each rib's own drawing.
- At every crossing the overlap [t0, t1] of the two ribs along the common line is split at its midpoint m. With "A from below", rib A gets a slot from its lower edge up to m and rib B from m to its upper edge (and the reverse for "A from above"). The slot runs 1 mm past the rib's edge so it opens cleanly, and is T + lap play wide. Crossings shorter than 2·T are left unjoined (CROSSING_TOO_SHORT); rib pieces that cross nothing are reported as NO_JOINT (new code).
- The partner's id is engraved beside every slot (rotated along it), and the rib's own id where it still fits. Ids: A01..., B01...; pieces A03-a, A03-b.
- `baseRibs` is kept in the params but not used yet (no extra base frame).

### D45. Parametric P3: section clean-up keeps corners
- Found while checking the stacked mountain: the smoothing step ran Chaikin on the already simplified outline, whose long straight edges let one pass cut 40-50 mm off a rectangle's corners. Edges are now split to at most 2 mm before smoothing, so a pass cuts at most 0.5 mm off a corner and only facet noise is smoothed.
- The minimum-feature opening now uses miter joins instead of round ones, so it no longer rounds every convex corner by half the minimum feature (a box rib is a true rectangle). Thin features are still removed exactly as before.
- Both are tested: a 200 x 150 rectangle survives smoothing 0 / 0.5 / 1 with less than 4 mm² lost, and the box waffle ribs are exact notched rectangles.
- Label search speed-up (same placements): before the sampled "rectangle inside" check, a candidate centre must lie in the intersection of the shape shifted by the label's four corners. Hollowed layers (thin rings) went from about 3.2 s to 0.3 s for a 33-layer sphere, which also removed an intermittent test timeout.

### D46. Parametric P3: methods write their own guide steps; regression snapshots
- Every method returns its assembly steps (`SliceResult.guide`); the guide SVG only adds "Cut all N sheets" in front. The subtitle names the method.
- The brief's "regression" item is covered by file snapshots of the part outlines (rounded to 0.01 mm) for the analytic cases: sphere parallel, sphere stacked, box waffle (`lib/parametric/__tests__/__snapshots__/*.json`). They were first written in P3; they are not a golden for the Hinge Box.

### D47. Parametric P4: radial fins and hubs
- **Axis as a letter.** The brief lists `axisDirection: [x, y, z]`; the params use `axis: "X" | "Y" | "Z"` plus an optional `axisPoint` (null = centre of the model's bounds). Every case in the brief (wall clock, lamp shade) is axis-aligned, and a letter gives a stable frame for each fin: Z → e1 = X, e2 = Y; Y → e1 = X, e2 = −Z; X → e1 = Y, e2 = Z. Fin at angle θ: u = cos θ·e1 + sin θ·e2, w = axis, n = u × axis. An arbitrary direction can be added later by rotating the model instead (Source → Turn).
- **Angles.** A full turn (span ≥ 360°) spaces the fins evenly without repeating the end; a part turn includes both ends.
- **Fins are half-planes.** The section through the axis is clipped to x ≥ innerRadius, so fins θ and θ + 180° are separate parts. Ids R01..., pieces R03-a....
- **Hubs.** With hubs, each fin gets an inner strip hubWidth wide along the hub (so a fin whose model section starts further out still reaches its slots) and a tab T deep into each hub ring. Hub rings (H01 at the low end of the axis, H02 at the high end) are annuli from innerRadius to innerRadius + hubWidth, with one radial slot (T + play wide) per fin and a tick engraved by R01's slot. Pieces that end up without a tab are reported (FLOATING_PIECE).
- **Collisions at the hub.** Neighbouring fins need an arc of at least T + 1 mm at the hub radius: innerRadius × step ≥ T + 1. Otherwise FINS_COLLIDE_AT_HUB with `data {maxCount, minRadius}`, maxCount = floor(span·r / (T + 1)) (+1 for a part turn). The brief's case (T 3, r 20, 360°) gives 31. The Method panel offers both fixes as buttons.
- **Radial-profile formula.** `height = f(theta, s)` with theta in radians round the centre and s = r − r0, for r0 ≤ r ≤ r1 (`domain.x = [r0, r1]`), heights clamped to at least `base`. It is both a closed polar solid on the wall (so every method can slice it) and, with "Fin shape from: Radial formula", an exact fin outline drawn directly without slicing (the model is then not used and is hidden in 3D). If the source is not a radial-profile formula, choosing "Radial formula" switches the source to the default radial profile and the axis to Z. A test checks that the direct and sliced outlines agree within 1 % of the area.

### D48. Parametric P4: fins along a curve
- **Guides.** Ellipse (given as width × height, like every other size in the app) and circle. The brief's "imported SVG path" and "spline drawn in the editor" are not built in this run; the curve code works from an arc-length table, so another closed curve only needs a point-and-normal function.
- **Placement.** Fins are spaced equally by arc length (count, or "auto" from `spacingAtGuide`). Each fin stands on the guide along the analytic outward normal (ry cos φ, rx sin φ); its frame is U = normal, W = Z twisted by τ about U, N = U × W. The test checks the normal within 0.01°.
- **Formulas.** finLength(t), finHeight(t, s, L) and twist(t) are formula strings using t (0..1 round the guide), s (mm along the fin) and L (its length). The outer boundary is none, an ellipse, or a polar formula r(phi) that clips the fins (ray from the guide point along the normal). A formula that gives no number anywhere is an error, not silently skipped.
- **Twist.** A twisted fin meets the plate at an angle, so its slot is widened to (T + play) / cos τ; the guide tells the user to push the fins in at the slot's angle.
- **Collisions.** Neighbouring footprints closer than T + 0.5 mm are trimmed back to where they are far enough apart; if they already touch at the guide they are reported (FINS_COLLIDE with the t range). Fins shorter than max(min feature, tab width + 2) are dropped (SHORT_FIN_DROPPED).
- **Back plate.** The outline is the outer boundary when there is one, otherwise the convex hull of the fins plus `backMargin`. Its slots are stored in fin order, so the guide drawing names each one. Centre feature: clock-insert hole (Ø + 0.2 mm press fit; 30, 37, 50, 60 mm offered), opening (the guide curve), or mirror (the guide shrunk by 3 mm). The plate's local y runs up the wall, so the assembly guide draws it flipped to show the front.
- **Leaf clock preset.** "Load the leaf clock" sets: oval guide 120 × 76, 56 fins, length 200 clipped by a pointed lens outline r(phi) = 1 / ((|cos phi|/165)^1.25 + (|sin phi|/100)^1.25)^0.8 (330 × 200 mm), height 4 + (14 + 10 cos²(2πt))·|sin(πs/L)|^0.7, twist 12 sin(2πt)°, 60 mm clock insert. The first outline tried (a polar peanut) did not read as a leaf. `abs()` in the height keeps the 0.7 power defined where sin(πs/L) rounds to a tiny negative number at s = L.

### D49. Parametric P4: viewer and result
- `SliceResult` now carries `method` and `usesModel`. When the parts come straight from formulas (along a curve, radial formula) the source model is hidden in 3D and its warnings are not shown, and `bounds` are the parts' bounds.
- Explode: radial and along-a-curve fins move outward along their own length; hubs and plates keep the per-family rule. Their plane rectangles in 3D are drawn only round the fin, not across the whole model.
- The Slice Inspector hides the "Plane ... along X" row for these fins (it means nothing for a fin turned round an axis).
- The ellipse test recovers the fin's start point from its outline, which sits on the 0.001 mm Clipper grid, so it slides that point along the fin onto the ellipse and requires the shift to be under 0.001 mm. The slot positions are still checked within 1e-6 mm, from the unrounded tab coordinates.

### D50. Parametric P5: depth model and where it runs
- **Model.** Depth-Anything-V2-Small, the int8 quantized ONNX from onnx-community (27 MB, Apache-2.0). Base and Large are CC-BY-NC, so they are never offered (noted in `public/models/LICENSES.md`). The quantized file was chosen over fp32 (99 MB) for download size; on the test portrait the depth map is clean and the whole photo → fins run takes about 4 s on WASM.
- **Runtime.** onnxruntime-web 1.30 in a module worker (`components/parametric/depth.worker.ts`), loaded from `/ort` with `webpackIgnore` (the same pattern as manifold) because bundling ORT's wasm loader through webpack is fragile. WebGPU when the browser gives an adapter, otherwise WASM (single thread unless the page is cross-origin isolated, which this app is not).
- **Model file.** Not committed (git-ignored, `npm run fetch:depth-model`). The worker tries `NEXT_PUBLIC_DEPTH_MODEL_URL`, then `/models/...`, then Hugging Face, with download progress in the status line. Alternatives: commit it (27 MB in git, rejected) or always load from Hugging Face (rejected: a third-party request for every user, kept only as the fallback).
- **Pre/post-processing** in `lib/parametric/source/relief.ts`, so it is unit-tested: long side 518, both sides multiples of 14, ImageNet mean/std, NCHW; the output (relative inverse depth, larger = nearer) is normalised by its 1st–99th percentiles.
- **Storage.** The photo itself is not kept: IndexedDB stores the packed depth map (a small binary with a magic number) plus two small previews (photo and depth). The project JSON stores only the file name and the relief settings, like an imported 3D file. A project whose photo is not on this device falls back to the library model with a message.

### D51. Parametric P5: relief from the depth map
- **Mesh.** A cell-mask heightfield: a grid over the depth map (8–256 cells on the long side, "Detail"), a top surface over the inside cells, a flat back at z = 0 on the wall, and walls along the mask boundary. It is watertight by construction and goes through the same `prepareMesh` as an imported model, so every method can slice it.
- **Heights.** max(0.5, base + v · max depth), v the processed depth (invert, Gaussian smoothing in depth-map pixels, gamma). The field labels are "Smoothing" and "Contrast" (gamma) because those are the words a maker uses.
- **Subject mask.** "Cut away" keeps cells nearer than the 35th depth percentile, then the largest 4-connected region, with holes filled and single-corner pinches removed in a loop (a pinch would make the surface non-manifold, a hole would make it genus 1). "Keep" uses the whole rectangle. The brief's hand-painted mask brush is not built in this run; the automatic mask plus "Keep" covers portraits and objects on a plain background.
- **Size.** The relief is sized by its width in mm (200 by default) rather than by pixels, so the photo's resolution does not change the sculpture's size.
- **Honesty.** The Source panel says that depth from one photo is an estimate and that a 3D scan or model gives better faces.

### D52. Parametric P5: deviation and fidelity
- **Sampling.** 2000 points spread over the source surface by area, from a seeded generator (mulberry32), so the score is the same on every run. Triangles flat on the wall (the relief's back, a model's cut face) are skipped: no part should cover them. For parallel fins only points in front of the wall (z ≥ 0) count, because the sculpture only shows the front half of the model.
- **Distance.** From each point to the nearest part, each part treated as its real solid (outline extruded to thickness T at its placement), with a cheap lower bound to skip far parts. No BVH library (three-mesh-bvh) was added: parts are planar, so point-to-prism distance is exact and fast enough (the 42-part portrait slices, deviation included, in about 220 ms).
- **Fidelity** = clamp(1 − mean / (2 · spacing), 0, 1), where spacing is the method's own gap: fin spacing for parallel, T for stacked, the average of the two spacings for waffle, the arc gap at the mean radius for radial, the spacing at the guide for along a curve. 100 % means every surface point lies on a part; a mean deviation of one full gap gives 50 %.
- **Heat map.** Coloured points (blue = on a part, red = a full spacing away), drawn in 3D with a legend, toggled by "Deviation". Points rather than a coloured mesh because the samples are the measurement and need no extra geometry.
- Computed in the slicer worker after each slice and only when the parts come from a model (not formula-only methods).

### D54. Parametric P6: what Free can do
- **Rule.** Free = a library model sliced as parallel fins, at most 30 parts (`FREE_PARAMETRIC_PARTS`), exported with the HingeLab mark. Everything else (3D file, photo, formula sources; stacked, waffle, radial, along-a-curve methods; more than 30 parts) needs Pro. One function, `parametricLocks(plan, params, partCount?)` in `lib/plans.ts`, lists what is locked, and the control bar, the dock, the export buttons and the server all use it, so they cannot disagree.
- **Preview is free.** A Free user can pick a locked method or source and see the result in 3D and on the sheets; a "Pro:" note in the Analysis panel names what is locked, and exporting opens Upgrade to Pro. Alternative: disable the locked buttons (rejected: seeing your own design as a waffle is the best reason to upgrade, and the hinge box and letters products already work this way).
- "Along a curve" builds its fins from formulas, so its source is not checked separately; the method itself is the Pro lock.
- **Where the 30-part limit is enforced.** At export (in the browser and again on the server), not in the database: the count is only known after slicing, and Free sculptures are not saved in the cloud anyway (D55).

### D55. Parametric P6: cloud projects are Pro

### D56. Parametric P6: exports and the mark
- **Free exports are built on the server.** The browser sends the params to `/api/export` (`product: "parametric"`, `what: zip | guide | sheet`); the route reads the plan from the session, checks the locks, slices again with manifold on the server, checks the part count, and adds the mark. The plan rules cannot be bypassed by editing the page. Pro exports are built in the browser (no round trip, works with 3D files and photos that only exist on the device).

- **The mark** is the same as the other products: an 8 mm strip below each sheet with "Made with HingeLab" (`addWatermark`), so it never overlaps a part. A first draft drew it inside the sheet and could cover a fin. The assembly guide is not marked: it is instructions, not a cut file.

### D57. Parametric P6: model files in Storage
- Private bucket `models` (100 MB per file, the same limit as the 3D-file import). Path `{userId}/{projectId}/{uuid}-{name}`. Policies: users read and delete only their own folder; uploading needs the profile's plan to be `pro` (the Storage policy checks `profiles.plan`), so a Free user cannot store files even by calling the API directly.

- Photos: the packed depth map is uploaded (it is what the relief is built from), not the original photo; the small depth preview is rebuilt from it after download, and the photo preview is not stored.
- Duplicate copies the file into the new project's folder; delete removes the project's files.
- `supabase/config.toml` sets the local file size limit to 100 MiB; on hosted Supabase the same value must be set in the dashboard (SETUP.md).

### D58. Parametric P6: cut-time estimate
- minutes = (cut length × passes / cut speed + score length / score speed + contours × 0.4 s × passes) / 60. The 0.4 s per contour stands for the pierce and the move to the next start point, which dominate on sculptures with many small parts.
- Presets per material for a typical 40–60 W CO2 laser (mm/s): birch 3 mm 12, birch 18 mm 11, poplar 3 mm 15, MDF 3 mm 10, card 2 mm 30, acrylic 3 mm 8; scoring 150 (card 200, acrylic 120). A custom material uses 36 / T mm/s and two passes above 6 mm.
- Shown as "about N min" in Analysis (the tooltip gives the speeds used) and in step 1 of the assembly guide. It is labelled an estimate because it does not know the user's machine. Alternative: let the user enter their own speeds (not built in this run).

They now sign in as a fresh Pro user from the local stack (`signInAsPro` in `scripts/shots/lib.mjs`) and delete it at the end; what they check is unchanged. `parametric-p6.mjs` checks the Free and Pro gates and a cancel through a signed test-mode webhook.

Revisit only if S2 performance budgets fail with large documents (then: canvas rendering of the same model).

### D64. Studio: languages
- next-intl is not added yet: the UI is English only (standing rule) and every string is still in the components. Strings will be moved into message files when a second language is actually planned.

### D65. Studio: Storybook with Vite
- Storybook 10 with `@storybook/react-vite` (the Next.js framework adapter brings webpack and server-component handling we do not need for client-only UI components). `.storybook/main.ts` aliases `@` to the project root; `preview.tsx` loads the tokens and adds Theme and Accent toolbar switches. `@vitejs/plugin-react` is pinned to 5 because 6 needs Vite 8, which Storybook 10.6 does not support yet. `npm run build-storybook` writes `storybook-static/` (ignored by git).

### D66. Studio: local projects
- Projects that are not in the cloud live in IndexedDB (`hingelab-studio`: `projects` and `assets` stores) with ids prefixed `local-`, so `/editor/<id>` tells local from cloud projects without a lookup. They autosave 1.5 s after the last change, with a thumbnail. Guests can create and open local projects; the Projects page lists them too, and S4 adds cloud projects beside them.
- `.hingelab` files are ZIPs (`document.json`, `assets/`, `thumbnail.png`, `manifest.json`) written with a fixed modification time so the same document always gives the same bytes. Opening checks the schema version, runs migrations, refuses files from a newer version with a readable message, and limits unzipped size to 300 MB.
- Opening a legacy single-product project file (the earlier Hinge Box / Letters / Parametric JSON) does not convert it: a toast offers to open it in the classic editor, which already reads it. Conversion comes with the generator wrappers (S5, S7, S8).
- Opening a file whose name already exists adds " (2)" instead of overwriting.

### D67. Studio: thumbnails are built from numbers only
- Thumbnails are SVG strings shown with `innerHTML`, so `documentThumbnail` forces every value it writes to a finite number and `assertDocument` refuses sheets whose position or size are not finite numbers. A crafted `.hingelab` file therefore cannot inject markup. The sheet colours use the theme variables with the dark colours as fallback (the PNG inside the file has no CSS).

### D68. Studio: design tokens and the old editors
- `styles/tokens.css` defines the three themes (dark default, darker, light) and four accents, the 30 cut-layer colours (LightBurn's C00–C29 palette, so files keep their meaning when moved between tools) and spacing, radii, type and motion. It also defines the old variable names (`--panel`, `--fg`, `--sheet`, …) as aliases, so the classic editors follow the chosen theme without being rewritten. A tiny inline script sets the theme before first paint to avoid a flash.

### D69. Studio: number fields
- Every numeric field (`NumberInput`) accepts expressions (`25.4*2`, `3in`, `+10`, `*=2`, `50%`), parsed by a small recursive-descent parser (no `eval`); a comma is read as a decimal point. Values are stored in mm and shown in the document's units. Arrow keys step (Shift ×10, Alt ×0.1), dragging the label scrubs, Alt+click or the ↺ button resets to the default, and the right-click menu offers reset, copy/paste and lock.
- Changing the sheet width or height in the editor renames the sheet to "Custom size", so it is never labelled "A4" at a size that is not A4.

### D70. Studio editor: the document store and history
- One zustand store per open document holds the document, selection, tool, view and UI toggles; edits are immer recipes, and history keeps the inverse patches of the last 200 steps (`lib/studio/history.ts`). Drags and scrubbing preview from a frozen base and become one step when released; typing and arrow nudges merge by key. Alternative: snapshots of the whole document per step (simpler, but large documents would use too much memory).
- Some state is a cache, not an edit: text outlines, and the grid / snapping toggles. These change the document without an undo step (`quiet`), so Undo never just "un-shapes" a word or flips a view toggle.

### D71. Studio editor: geometry conventions
- Matrices are `[a, b, c, d, e, f]` in mm with y pointing down. The selection box is axis-aligned in document space even for rotated objects (rotated boxes like Illustrator's "bounding box follows object" come later if users ask). Live shapes keep their parameters; editing a shape's anchors with Direct Selection converts it to a plain path first and says so in a toast.
- A star's inner radius is stored as a ratio of the outer radius (shown as %), so scaling the star keeps its look.
- A compound path is one path node with several subpaths filled even-odd; a clipping mask is a group with role "clip" whose first child is the mask. Both stay plain JSON that every exporter already understands.

### D72. Studio editor: text
- Text size is the em size in mm, tracking is in 1/1000 em (never added between joined Arabic-script letters), and outlines come from HarfBuzz + opentype.js as Bézier curves. Outlines are saved with the document so files open without fonts; any change to text or settings re-shapes them in the background.
- Characters the font lacks are reported in a toast (letters brief: missing glyph = `.notdef`) rather than silently substituted from another font. Typing Persian needs a font that has the glyphs (Vazirmatn, Lalezar, Noto Arabic); automatic per-run font fallback is a possible later improvement.
- With the Type tool active and no text selected, the control bar shows the Type tool's defaults (font, size, …) even if another object is selected, as in Illustrator.

### D73. Studio editor: shortcuts
- Every command lives in one registry (`lib/studio/commands.ts`) that drives the menus, shortcuts, context menu and command palette, with four sets (HingeLab/Illustrator-compatible, CorelDRAW, LightBurn, Inkscape). Ctrl+N, Ctrl+T and Ctrl+W belong to the browser and cannot be overridden reliably, so no command uses them and New is Ctrl+Alt+N; Redo is Ctrl+Shift+Z only (Ctrl+Y opens history in some browsers).
- Custom shortcuts and workspaces are kept in localStorage (`hingelab-keymap`, `hingelab-workspace`) until cloud preferences exist (S4). Assigning a key that is in use asks before moving it; the file format for export/import is `{format: "hingelab-shortcuts", version: 1, set, bindings}`.
- The palette's fuzzy match only accepts scattered letters when each piece starts a word or continues inside the previous piece's word, so "star" no longer matches "Assign to C00".

### D74. Studio editor: layout
- The dock is one tabbed column (tabs reorderable, wrapping onto a second row when narrow); floating and split panels are deferred to S10. Workspaces (Essentials, Laser, Typography, Minimal) choose which panels are shown.
- New objects go on cut layer C02 ("Cut", red) so they are visible and cut by default; C00 is black and is drawn in the theme's ink colour so it stays visible on the dark canvas.

### D75. Studio editor: clipboard and revert
- Copy writes our own JSON to localStorage and an SVG (mm, cut-layer colours as strokes) to the system clipboard, so pasting into Illustrator or Inkscape works. Pasting SVG from other programs into the editor waits for the S3 importer.
- File → Revert goes back to the document as it was opened in this session, as an undoable step.

### D76. Parametric: Text source
- Text is shaped on the main thread with the Letters runtime (HarfBuzz + bundled fonts, cap height = the Height field, `direction: auto` so Persian is right-to-left) and sent to the slicing worker as packed outlines, so the worker needs no fonts. The outline key is the text, font, size and spacing; depth and profile changes re-slice without re-shaping.
- Outlines are unioned (nonzero) so overlapping or joined glyphs make one solid; holes (the counter of "O", "a") are kept.
- Two profiles: Flat (an extruded solid, every fin full depth) and Rounded (a pillow relief: height rises over the Rounding distance from the edge to the full depth, built on the photo-relief grid). Rounded is the default because it shows the fin rhythm best.
- Missing glyphs are reported under the font picker instead of falling back to another font, as in Letters.

### D77. Parametric: tabs per fin, and tabs that really join

### D83. Fit to sheet (U4)
- **`lib/fit/fitToSheets.ts`** is pure and product-agnostic: given `build(scale)` (the product rebuilt at a scale, as part boxes), a sheet and a target count N, it returns the largest scale in [0.05, 1] at which every part nests into N sheets. It scans down from an area estimate until something fits, then bisects to 0.4 %, so the result fits and the scale just above it (`upper`) does not. Packing reuses the Parametric MaxRects nester with rotation off (grain "along-x"): parts stay upright, so labels, hinge direction and the reading order of letters are as designed. A Hinge Box fit takes 1–11 ms; a five-letter word about 100 ms.
- **Only the product size scales.** Hinge Box: W, D, H, diameter and corner radius (the radius never drops below T + 1 mm). Letters: letter size, spacing, box depth, stencil border (and the island area by scale²). Material, kerf, hinge lattice, tabs and slots keep their sizes. Scaled lengths are rounded to 0.1 mm.
- **Fit only shrinks.** "Fit product to 1 sheet" never enlarges a design that already fits; enlarging to fill a sheet surprised more than it helped in trials, and the size fields stay what the user typed. The Sheet section shows the result ("Scaled to 71.3 % · 99.8 × 64.2 × 49.9 mm · 1 sheet") and the status bar repeats it.
- **Modes:** Off (default: today's row layout on one bed), 1 sheet, N sheets (2–20, stepper) and Auto (design size, nested on as many sheets as needed; a part larger than the sheet goes on its own oversize sheet, outlined in orange). The setting is `fit: { mode, sheets }` in the product params, so it autosaves, undoes and travels with presets and cloud projects.
- **Golden unchanged.** With Fit off, `arrangeHinge` / `arrangeLetters` call exactly the old `computeModel` + `layoutParts` / `layoutLetters`; a test exports all 198 golden cases through `arrangeHinge` byte-for-byte. The server exports (`/api/export`) use the same arrange functions, so the downloaded file is the fitted one.
- **Several sheets in one file.** Sheets are stacked top to bottom 30 mm apart in one layout; the canvas draws each sheet ("Sheet 2 of 3") and the SVG holds all of them (one file per sheet can come later with the export dialog).
- **Sheet presets** reuse `SHEET_PRESETS` (machine beds, paper, common sizes); a size that matches none reads "Custom size".
- **Parametric** keeps its own nester and sheet count. Scaling it to N sheets would mean re-slicing the mesh a dozen times in the worker; its "Target size" already sets the size. Revisit with U7's "Too many sheets" fix.

### D86. Checks with fixes and Auto-fix all (U7)
- **One model for all products** (`lib/issues`): an issue has a code, a level (error, warn, info), a message and fixes. A fix is a pure function from settings to settings with a label and a `safe` flag. - **Fixes are proven**: where a fix is not certain (turning the sheet, splitting the wall, fitting to N sheets, Serpentine) it is tried first and only offered if it clears the issue; Hinge Box stops after two that work to keep the check fast. Every fix in the tests removes its issue.

### D90. Jigsaw Puzzle generator (G2)
- **Layout**: the piece count picks a grid (rectangles score aspect error plus 30x the count error; other shapes count the cell centres that fall inside the outline). Grid lines are bent by a seeded random (mulberry32, "Layout number" with a Randomise button), and each shared edge gets one tab: classic (Draradech-style cubic knob), kids (bigger and rounder), wavy (no knob) or straight. The same seed always gives the same puzzle.
- **Cuts are single lines, not piece outlines**: each grid line is one joined path, clipped to the outline grown by a 0.5 mm overshoot plus half the kerf, so every edge is cut once, the laser never doubles back, and the ends run just past the border. The outline is its own cut. Pieces are still computed (cell polygons intersected with the outline) for stats, checks, numbering and the 3D view.
- **Shapes other than a rectangle**: a tab must stay inside the outline with a margin; otherwise it flips, then shrinks to 0.7, then becomes straight. Edges whose midpoint is outside are dropped. Pieces smaller than 0.42 of the nominal area are joined to a neighbour (the edge between them is removed) and reported in the stats. Tab curves that cross themselves are re-rolled smaller, up to 8 times.
- **Frame and tray**: a frame is a ring around the puzzle (hole = outline + clearance); a tray adds a solid base under the frame. The custom outline accepts an SVG path.
- **Engraving**: a picture (cover-fitted, zoomable, clipped to the outline), centred text, or piece numbers in reading order. Pictures are turned grey and shrunk to JPEG under 700 KB on the device, and exported as an `<image>` with a clip path in a "labels-images" layer under the engrave paths, so LightBurn/xTool treat it as an image engrave. `GenPart.images` and the canvas support this for every generator.
- **Pro**: more than 50 pieces needs Pro. The editor shows a "Needs Pro" note; on export the free plan gets the upgrade dialog, and Pro exports are rebuilt and checked on the server (`/api/export` with `{product, params}`, `lib/billing/exportGenerator.ts`), so the limit is not only in the client. The Photo 100 preset is marked Pro on the start page.
- **Checks**: pieces under 12 mm, necks thinner than 3 mm or the material, plain edges, tiny joined pieces, thin frame, missing picture, text too wide, missing glyphs; the safe fixes run in Auto-fix all.
- **Shared helpers** moved to `lib/generators/util.ts` (merge, file names, rail art fitting); the clock uses them and its golden is unchanged. Preset thumbnails drop points closer than 1/260 of the view and round to 0.1, which keeps puzzle thumbnails under 50 KB. A golden SVG (`lib/generators/__tests__/golden/puzzle-default.svg`) pins the default puzzle.
### D91. QR Code generator (G3)
- **Encoder**: `qrcode-generator` (MIT, about 7 KB gzip) builds the module matrix; text goes in as UTF-8 bytes, so Persian and emoji encode correctly. The smallest version that holds the content at the chosen level (L, M, Q, H) is picked. Content is written in the formats phones understand: `https://` added to bare addresses, `WIFI:T:…;S:…;P:…;;` with the reserved characters escaped, vCard 3.0, `mailto:` with encoded subject and body, `SMSTO:` and `tel:`. Too much content is an error that names the fix.
- **Module styles** (`lib/generators/qr/build.ts`): square (row runs unioned), rounded (the square union opened by 0.4 module, so convex corners round), dots and connected (circles, plus bars to dark neighbours). Finder and alignment patterns stay solid rounded rings in the dots and connected styles; scanners locate the code by them, and jsQR could not read dotted ones.
- **Outputs**: Engrave (the modules, or the background when Invert is on, on the Engrave layer); Cut out (a light top plate with the dark modules cut through, glued on a contrasting backplate shown dark in 3D and thumbnails via `GenPart.tone`; light pieces that come loose are counted and the notes say to lift the plate with transfer tape); Stencil (holes are each row's runs, thinned by the bridge so a strip of material runs the full width between rows; finder and alignment patterns are four bars in a pinwheel with a bridge at each corner, so their middle rows and columns, which scanners measure, stay unbroken). Nothing in a stencil falls out, except letter centres, which a check reports.
- **Plate**: rectangle or circle (the circle holds the whole quiet zone), border, corners, a frame ring in the border that keeps clear of the keyring hole, a label below, above or beside the code (Letters fonts), a centre logo (heart, star, Wi-Fi sign or up to four letters) that clears the modules under it, and a keyring tab on top or a hole in the corner.
- **Checks**: module size for the output (0.6 mm engraved, 1.2 mm cut out, 1.5 mm stencil; fix: a bigger code), the logo's share of the code against the level (none at L, 5 % at M, 9 % at Q, 14 % at H; fixes: level H when that is enough, otherwise a smaller logo), quiet zone under two modules, thin stencil bridges, letter centres in a stencil, a frame squeezed against the code, a keyring hole in the quiet zone, a Wi-Fi network without a password, missing glyphs.
- **Clipper**: `unionShapes` takes an opt-in `strict` flag (Clipper's StrictlySimple). Without it, a block of squares with a hole touching its outer (a finder ring) comes back as one outline with a slit instead of an outer and a hole, so loose pieces were not counted and the 3D slab was wrong. Existing callers are unchanged. The 3D view now builds each part from the even-odd union of its outline and holes, so islands inside holes are drawn.
- **Tests decode every output with jsQR**: each content type at each level, every style with every output, inverted, logos, label positions, round plates, frames and every preset are rasterised from the built geometry and decoded back to the exact content. A flood fill proves every stencil is one piece. `scripts/shots/g3.mjs` also renders the exported SVGs (Wi-Fi card, a logo at level H, a dotted stencil) and decodes them.

### D92. Boxes generator (G4)
- **One generator, seven designs** (`lib/generators/boxes/`): a finger-jointed box (closed, open, or a lift-off lid with a lip that drops inside the walls), a tray with half-lap dividers, a desk sign in a slotted base, a three-layer photo frame (window, photo layer open at the top, back with a keyhole or a stand), a phone or tablet stand, a key holder with hooks pushed through the board, and a bird house (pitched roof, entrance, vents, drain holes, optional perch hole). The design is a rail choice; each design has its own section, and only the jointed ones show the finger section. Written from scratch in the spirit of boxes.py; no code was taken from it. 14 presets.
- **Finger joints as edge ownership** (`joints.ts`): panels are cut at their outside size. Along each edge where two panels meet, the T × T column is split into an odd number of equal fingers (`fingerCount`, as close to the target width as possible) that the two panels own in turn; front and back own the end fingers on every edge and the T × T × T corner cubes, the sides own the end fingers top and bottom, and the bottom and top own none. Every finger therefore belongs to exactly one panel, so the panels always mate, at any size, thickness or finger width. Sizes are inside by default (things you measured fit), or outside with a toggle. The kerf is applied by the shell, so every finger, tab and slot tightens by the same amount.
- **Unions of touching rectangles**: Clipper's strictly-simple union split rectangles that only share an edge, and keeping the largest piece dropped fingers. Fingers now reach into the panel body and corner cubes into the next finger, and a plain union is used.
- **Tabs and mortises**: the sign, frame stand, phone stand and key hooks lock in with tabs that fill rectangular slots exactly; the phone stand's back rest leans at the chosen angle and its slots are cut along the slope.
- **3D placement**: `place` gains `yaw` (turns an upright part about the vertical, for side walls and hooks) and `tilt` (how far an upright part leans, for roofs and the phone rest), applied in `scene3d`. `lib/generators/place.ts` is the same transform as plain math (and its inverse), shared by the tests and the thumbnails. Larger y is nearer the viewer, so fronts (entrance, frame window, stand lip, hooks) face the camera. Below a 45° pitch the short roof panel starts a little down the slope, and the long one reaches past the ridge just far enough to cover it, so the two never overlap.
- **Tests in 3D**: every part's material is sampled and mapped into the assembly; each point must lie in exactly one part (no overlaps, for every design and preset), every point of a box's walls must be filled (no gaps; entrances and vents excepted), and every mortise must be filled by exactly one other part. Plus complementary finger spans, inside and outside sizes, the lid lip clearance, the half-lap crossing, roofs resting on the gables, fronts facing the viewer, every check and fix, and a golden SVG of the default box.
- **Checks**: fingers thinner than 1.5 T, edges with fewer than three fingers, compartments under 20 mm, text wider than the sign or board, hooks closer than 30 mm, a phone slot under 9 mm, an entrance too wide for the front, a photo overlap under 2 mm, a frame border too narrow, missing glyphs; each with a fix.
- **Thumbnails** of assemblies with turned or leaning parts are drawn in a three-quarter view (each part's face and edge band projected, painter's order by which side of each other's slab the parts lie); the other generators keep their front view and their thumbnails are unchanged.
- **Editor**: switching design renames the piece while it still has a built-in name; the 3D view reframes when the set of parts changes (another design), not while a size is dragged; dock sections whose only field is a rail choice are hidden. Budget: Boxes 10.0 KB gzip (15).


### D93. Lamina ideas: outline nesting, calibration bar, part labels, Folded method (G5)
- **Outline nesting** (`lib/nest/outline.ts`): each part's outline, grown by half the part gap plus three quarters of a grid cell (so the grid can only err on the safe side), is rasterised even-odd with its holes, as runs per row. Parts go largest first to the lowest, then leftmost, free position on the first sheet where any allowed angle fits; free-run tables let a blocked candidate jump past the cell that blocks it. Parts drop into each other's notches and into big holes, which box packing cannot do. The cell is 1 mm (coarser only on very large sheets). Parts larger than the sheet get an oversize sheet of their own, as before. Opt-in: Parametric gets a Nesting choice (By box / By outline) in Material, the generators get one in Sheet (quarter turns; parts with pictures stay upright). `outlinePacker` lives in `lib/fit/outlinePack.ts` so products that only pack boxes do not load Clipper (it had pushed the Hinge Box chunk over budget).
- **Calibration bar** (`lib/fit/calibration.ts`): a scored 100 mm scale (50 mm on narrow sheets) with millimetre ticks over the first centimetre, and a 10 mm square cut with the kerf compensation, which should measure 10.0 mm once it drops out. A 15 mm strip is kept free along the bottom of every sheet (the nesters pack into a shorter sheet). Opt-in checkbox in Parametric Material and in the generators' Sheet section. The scale goes on the score layer, the square on the outline layer.
- **Part labels** (generators): each placed part's name in the single-stroke font, scored where it fits clear of cuts and engraving (`finLabel`, the same placement as Parametric fin labels). Labels are placed after turning, so they always read upright. Parts with open cuts (puzzle boards) are not labelled: a name would run across the pieces. `label.ts` gains the glyphs , : ' / ( ) + &.
- **Folded method (papercraft)** (`lib/parametric/methods/folded.ts`): the model is simplified to the chosen face count by quadric edge collapse (`simplify.ts`: weld, area-weighted quadrics, link-condition check so the mesh stays a closed manifold, no flipped or sliver faces). Manifold's own `simplify` stalled at 700-4000 triangles and collapsed whole models at large tolerances, so it is not used. The faces are unfolded greedily into nets from the largest faces, flat edges first, then the longest; a face joins a net only if it overlaps no face already there (SAT, 0.01 mm), leaves no wedge under 6 degrees at a shared corner (which would close into a slit), and the net still fits the sheet less margins, tabs and the calibration strip. Joined edges become folds: mountain folds are solid score lines, valley folds dashed (2.5 mm on, 1.5 mm off); flat joins get no line. Cut edges are numbered on both sides and get a trapezoid glue tab on the side that keeps more of it after trimming against the net (at least 40 %, otherwise a NO_TAB warning says to tape that edge). Nets always nest by outline; the 3D view shows the folded model's faces (flat shaded, exploding along their normals). A Folded choice on the method rail (Pro, like the other non-parallel methods) switches to 0.3 mm card when the material is thicker than 1 mm, and the dock warns while it is. Presets: Papercraft ball (80 faces) and Folded head (150 faces), with net thumbnails.
- **Parametric export**: parts gain `score` (open scored lines) and `faces3d`; `sheetSVG` writes a "Score lines" layer when there are any, and the calibration bar.
- **Tests**: outline nesting (frame with parts in its hole, interlocking L shapes, extra and oversize sheets; every part inside the margins and the grown outlines never touch), decimation (reaches the face count and stays a closed manifold), folded nets for the sphere, torus and head (one piece per net, each face once, no edges crossing, net area at least the faces' area, numbers engraved, no nets overlapping on the sheets, the calibration strip kept clear), the folded presets, box nesting with the strip, and for every generator: defaults identical with or without the extras, outline nesting of every preset on the sheets and apart with a calibration bar per sheet, labels inside their parts on the score layer.

### D94. xTool Studio gaps suited to SVG generation (G6)

### D95. Security hardening (audit, see SECURITY_AUDIT.md)
- **SVG output is escaped at the source** (`lib/security/svg.ts`). Every comment goes through `xmlCommentText`, which splits every "--" so no run of dashes can end it (the old `--` → `- -` replacement turned `--->` into `- -->`). Picture hrefs are escaped and only base64 PNG/JPEG/WebP data URLs are kept (`isImageDataURL`, also enforced in `mergePuzzle`), which closes a stored XSS: a puzzle picture of `"/><script>` was written into the server's SVG unescaped. Project thumbnails pass `inertSvgMarkup` before `innerHTML`.
- **Downloads never run as a page**: every file from `/api/export` is `content-disposition: attachment`, `nosniff`, `cache-control: no-store` and carries `default-src 'none'; sandbox` (`downloadHeaders`). The site-wide CSP skips `/api/*` so it does not replace that.
- **State-changing API routes** (`/api/export`, `/api/stripe/checkout`, `/api/stripe/portal`) refuse cross-site requests (`Sec-Fetch-Site` / `Origin`, 403) and anything but `application/json` (415), so an HTML form on another site cannot post to them with the victim's cookies. Bodies are size-checked before parsing. The webhook keeps its Stripe signature check on the raw body.
- **Server-side input validation**: Hinge Box and Parametric requests outside the editor's ranges are refused with 400 (`lib/billing/validate.ts`: enums, finite numbers, slit count at most 400 000, Parametric fields that apply, icosphere detail 0-6, formula length 2000). Generator settings are clamped to the fields' own ranges (`lib/generators/sanitize.ts`), the same thing the editor does. Every built-in preset passes unchanged (the Parametric thickness bound is 0.1 mm because of the 0.3 mm card presets).
- **Rate limits** (`lib/security/rateLimit.ts`): export 40/min, Parametric export 12/min, checkout 10 per 10 min, portal 20 per 10 min, per user id (or per IP when signed out, from the platform's `x-vercel-forwarded-for`). Counted in Postgres (`public.rate_limit_hit`, service role only, keys stored as SHA-256) so all instances share it, and in memory as a fallback. `/api/export` has `maxDuration = 60`.
- **Database** (`20261011000100_security_hardening.sql`): `enforce_plan_limits` and `limit_user_presets` take a per-user advisory lock, so parallel inserts can no longer pass the 3-project and 200-preset limits; `keep_owner` triggers stop a row's `user_id` from changing; project params are capped at 1 MB; trigger functions are not executable by API roles; the `models` bucket accepts only 3D and photo MIME types. Applied to the hosted project with `npx supabase db push` (with the pending `user_presets` migration).
- **Plans**: `currentPlan` treats a production deployment without Supabase configuration as Free (it used to unlock Pro). A deleted or cancelled subscription keeps Pro when the customer has another active, trialing or past-due one (`otherProSubscription`).
- **Headers** (`next.config.ts`, `lib/security/headers.ts`): CSP (`default-src 'self'`, scripts from self plus `'unsafe-inline'` for Next.js and the theme script and `'wasm-unsafe-eval'` for manifold, HarfBuzz and ONNX, connections to Supabase and Hugging Face, `object-src 'none'`, `frame-ancestors 'self'`, `base-uri 'self'`, `form-action 'self'`), HSTS on Vercel, X-Frame-Options, nosniff, Referrer-Policy, Permissions-Policy, COOP; `poweredByHeader: false`. Checked page by page with `scripts/security/csp-check.mjs` (no violations, 3D view, Letters fonts and photo relief work).
- **Errors**: Letters export shows only messages written for users (`FontError`); other failures are logged and a generic message is sent.
- **Dependencies**: `postcss` forced to 8.5.29 (overrides), Vitest 3 to 4.1.11 (tinypool and mocker advisories), `vite-node` 5 added for `build:shape-icons`. `npm audit`: 0 vulnerabilities.
- **Tests**: `lib/security/__tests__/security.test.ts` (escaping, comment breakout, data URLs, thumbnail guard, the puzzle picture through merge, SVG and server export, request checks, limiter, headers, generator clamps and every preset, Hinge and Parametric validation with every preset, webhook with a second subscription) and `db.integration.test.ts` (rate limiter grants, 8 parallel inserts keep 3 projects, owner and size locks, no self-upgrade). `scripts/security/attack-check.mjs` sends the attacks to a running server.

### D96. Windows desktop app (Tauri 2) as an untrusted client of the website

**Context.** The owner asked for a professional Windows 10/11 app with an installer and secure auto-updates, keeping the web app, and treating the EXE as untrusted: no geometry, plan authority, payment authority or secrets in it.

**Decision.**
- **Tauri 2 (stable 2.12), not Electron**: a 2 MB per-user NSIS installer, the system WebView2, a Rust core that owns HTTP, tokens and files, and capability-based IPC. The UI (`desktop/src`, React 19 + Vite) is separate from the Next.js app and talks only to the Rust core. Tauri 3 alphas were not used.
- **All geometry stays on the server.** `/api/desktop/generate` runs the website's own export path (`lib/desktop/products.ts`, sharing `exportHingeForPlan` / `exportGeneratorForPlan` logic, `serverBuildContext`, validation and clamps) and returns settings, form state, checks and the SVG. The catalog is plain JSON. A build scan (`scripts/desktop/scan.mjs`) fails if server-only text or any secret reaches the bundle.
- **Pro designs on Free get no SVG** (403 with a message): whatever reaches the app can be saved, so the server is the only gate. Free designs carry the website's Free mark. The desktop plan is Pro only while the paid period plus 3 days' grace lasts (the web's `currentPlan` is unchanged).
- **Sign-in**: system browser + PKCE S256 + loopback redirect (RFC 8252/7636) to a consent page (the app sends only its loopback port; the server builds `http://127.0.0.1:<port>/callback`, because Next.js rewrites a literal 127.0.0.1 inside request URLs to localhost, which broke the full `redirect_uri` on the live site); one-time codes (120 s); opaque random tokens (access 15 min, refresh 30 days, rotating, reuse revokes the session), hashed in `private.desktop_*` tables reached only through service-role functions (migration `20261012000100_desktop_sessions.sql`). Tokens live in Windows Credential Manager and never reach the WebView. We did not use Supabase's own OAuth for the app because it would have put Supabase session tokens (usable directly against the database API) on the PC.
- **API contract**: `x-hingelab-client: desktop/<v>`; 401/403/422/426/429/503 mapped to typed errors; 426 when below the minimum version (`stable.json`, raised by `DESKTOP_MIN_VERSION`); rate limits 120 generates per minute per user and 30 token requests per 10 minutes per IP.
- **Updates**: official Tauri updater, minisign key (private key outside the repo, public key in `tauri.conf.json`), HTTPS endpoint on the website reading a Git-reviewed manifest with a host allowlist, `requireSignedVersion` (the signature must name the announced version, stopping replays of older signed installers), no downgrades, passive install, mandatory updates via 426 without loops. Release scripts verify signatures independently (`scripts/desktop/minisign.mjs`).
- **WebView lockdown**: strict CSP without remote content, navigation limited to the app, no fs/shell/http/opener permissions for the UI, SVG preview as `<img src=blob:>`, saves write only the server's last SVG by id.
- **Code signing**: not faked. Installers are Authenticode-unsigned until the owner gets Azure Trusted Signing or an OV/EV certificate (`WINDOWS_RELEASE_CHECKLIST.md`); SmartScreen guidance is in the app's Help.

**Consequences.** Editing needs a connection (previews come from the server); the app caches the catalog, account, recent designs and settings so it opens instantly and keeps the last preview offline. Every server change must stay compatible with installed versions or raise the minimum version. Docs: `DESKTOP_ARCHITECTURE.md`, `WINDOWS_BUILD.md`, `WINDOWS_RELEASE_CHECKLIST.md`, `DESKTOP_UPDATE_SYSTEM.md`.

## D101. The website's editors inside the desktop app

The owner found that much of what the website offers online (Letters, Parametric, the full editors with 3D view, DXF and sheet fitting, the Studio, cloud projects, the help centre) was missing from the EXE, and chose to show the website's own pages inside the app, signed in automatically, over rebuilding them natively. Rebuilding would have meant shipping or duplicating editor code in the EXE, against the rule that generators stay on the server, and every website change would need a second implementation.

How it works. A second webview (label `web`) sits over the app's content area (`Window::add_child`, Tauri `unstable` feature); the React UI keeps a placeholder and sends its bounds, hides the view on native pages and while a dialog is open, and keeps its page between visits. The first open of a run calls `POST /api/desktop/web-session` with the desktop bearer token; the server creates a one-time email sign-in token for that same user (Supabase admin `generateLink`, no email sent) and returns a same-site `/auth/callback?token_hash=...&type=email&next=...` path, which the website's existing callback turns into its normal session cookie. `next` passes `safeNext` and may not point at `/api/` or `/auth/`; the endpoint is rate-limited (20 per 10 minutes per user). A page that later lands on `/login` is signed in again, at most once a minute. Test builds use `localhost` for the view because Next.js rewrites `127.0.0.1` in redirects and the cookie must match.

Trust boundaries. The website view gets no IPC: capabilities now name the `main` webview (`"webviews": ["main"]`) and list no remote URLs, and the E2E test calls six commands from the view to prove they are refused. Only the website's origin loads in it; other `https`/`mailto` links (Stripe checkout included) and new windows to other sites open in the default browser; `file:`, `javascript:`, `tauri:` and foreign `blob:` URLs are blocked. Downloads must come from the website's origin and be drawing or project files (SVG, DXF, ZIP, JSON, `.hingelab`, PNG, JPG, PDF, LightBurn, CSV, TXT); they get a sanitised unique name in the export folder (else Downloads), and refused ones raise one clear message. App sign-out ends the website session (`POST /auth/signout`) and closes the view; `clear_all_browsing_data` is not used because it would also wipe the app UI's local storage.

Prototype freeze. Tauri's `freezePrototype` injects `Object.freeze(Object.prototype)` into every webview with no per-view switch, and a big-number library in the website's editors assigns its own `toString`, which throws on a frozen prototype ("Application error" in the Letters editor). The setting is off; `desktop/src/harden.ts`, the first import of the app UI, freezes the prototype instead and checks the result so the bundler keeps the call, and the root `package.json` lists it under `sideEffects` (the CSS-only list would otherwise drop the import). The E2E test checks the app UI is frozen and the website view is not.

Shipped as desktop 1.0.3 through the usual signed update.

## D104. Toppers are welded into one piece; mixed materials get their own sheets

A topper whose letters or motif fall apart on the bed is useless, so the build always ends with one part: the text and motif are unioned, grown by the weld or border, holes too small to cut are filled, and any island left (a dot, a separate word, a motif with a gap) is joined to the largest piece by a short straight bridge at the closest points. Motifs are built in code from circles, curves and polygons and unioned once (cached), rather than drawn as path data, so each one is a clean cuttable region at any size and the rail pictures come from the same geometry.

Hooks are separate parts whose tab is exactly the material thickness deep and passes through a slot in the board, so the arm's back rests on the board's face and glue holds the tab flush at the back. This needs no hardware, nests well, and the same profile function draws the rail picture, so the card matches the cut part. For heavy loads or thin sheets the same row can instead be holes for dowel pegs or pilot holes for cup hooks; picking the hook type sets a sensible hole size (8 mm dowel, 3 mm pilot) through the choice's `apply`, which the desktop app also honours.

Shaped boards (house, heart, cloud, arch) can put a hook slot or mounting hole outside the outline; that is an error with fixes rather than a silent clip, because a slot cut across the edge leaves a notch and a loose hook.

## D106. Sign inlays rely on kerf for the fit

An inlay is three cuts from two materials: the top board with the letters as holes, the letters themselves in the second material, and the letters' counters cut from the main material to drop back into them, all glued onto a backer. Because every hole shrinks and every outer grows by half the kerf, the inlay letters come out about one kerf larger than their holes and press in snugly without a separate clearance setting; the check warns when strokes are under 2.5 mm, which snap, and when the two materials differ in thickness. Keyholes on an inlay go only in the backer so the face stays clean.

Mounting holes are placed from the outline's real top edge at their x, not from the bounding box, so clouds, scallops, hearts and circles keep holes inside the board; a hole that still lands outside is an error, and one that cuts into the lettering is a warning with a bigger-margin fix.

## D107. Table numbers are one batch, one plate size

A set of table numbers is made at once, so the batch is a parameter rather than a copy-and-edit loop: a range or a list produces one plate per table in the same file, and the plate is sized to the widest table so the set matches on the day. The cap is 60 tables per file, which keeps the build and the nesting fast; above that the check offers to cut the range and suggests a second project.

Tabs sit where the plate's bottom edge is within a few millimetres of its lowest point, as far apart as the base allows; pointed shapes (hearts, diamonds, stars) get one wider centre tab instead of long legs. With two or three base layers the bottom one is solid, so the tabs are T × (layers − 1) long and never show underneath. Tent cards reuse the living-hinge idea of the Hinge Box: alternating slit rows across a band at the fold, solid at both edges, with the back half rotated 180° so both faces read upright once folded; acrylic cannot bend and is an error.

## D108. A trophy is one figure in a slot sized from its own material

The emblem, stem and name plate are unioned into one upright figure, so it cuts as one piece and cannot come apart; the stem starts from the emblem's real bottom on the centre line (a star's notch, a cup's foot), not its bounding box, and anything still separate is bridged. The figure's tabs follow the same rule as the table-number stands (D107): two where the bottom edge is flat, one wider tab under a point.

In a mixed build the figure is cut from the second material, so the slot width is the second material's thickness plus the clearance, not the base's. That is what lets a 5 mm acrylic figure stand snugly in a 3 mm plywood base. The clearance is a setting (0.1 mm by default, 0.05 mm suits acrylic) because the right push fit depends on the material and the laser, and the kerf compensation already makes the nominal sizes come out true.

## D109. Version 1 boxes keep their own build path

Every box that version 1 could make (a closed, open or lift-off box with finger joints and no engraving, a tray without a lid) is still built by the version 1 code, unchanged; the new shell, lids and designs live in a separate module that only runs when a version 2 option is switched on. A test fingerprints the parts of 19 version 1 designs, written and committed before any change, so a refactor that moved a single point would fail it. The migration writes the version 1 meaning (finger joints, no notch, no tray lid, no engraving) into old saves explicitly, so a later change of defaults cannot reach them.

The pin hinge puts the lid's back edge directly over the pin and leaves a gap of the lid's height above the pin plus its thickness to a fixed hinge strip. A lid that ran on past the pin would swing down into the back wall as it opened, and a smaller gap would stop it before upright, where it would fall shut. With the gap, the lid opens a little past upright and rests against the strip; a test turns the lid through 90 degrees about the pin and checks it never enters the strip or a wall. The cheeks that carry the pin sit inside the side walls and are round about the pin, so they turn in place.

The hexagon box's walls meet at their inside corners and leave a small V outside, filled with glue. Without bevels a laser cannot close a 120 degree corner, and making the walls longer would only move the gap inside or make them collide; tabs through the bottom hold the shape instead.

## D110. Job options that apply to every generator

We reviewed the xTool Creative Space generators and design library (box, puzzle, QR, sign, clock and name-tag makers, the material library and the batch-text and mirror tools) against HingeLab. HingeLab already covered most of what they offer and usually more (finger-jointed and living-hinge boxes with checks, kerf compensation, slotted stands, multi-material sheets). The gaps that mattered to people who sell what they cut were batch text (one set per customer name), mirroring for back-engraved acrylic, a wider material library, and a few popular shapes and styles: heart and flower clocks, puzzle outlines beyond rectangles and hearts, scan-me QR frames, neon-look signs and paint stencils. Those are what this phase adds; camera alignment, raster photo processing and machine control stay in the laser software.

Mirror and batch names live in their own `job` settings rather than beside the sheet extras, because saved designs and the server already check the sheet extras as exactly four fields. Both are applied in the one place every product passes through (the arrange step, which the editor, the server export and the desktop app all use), so they need no code in the generators. Mirroring happens after the kerf offset and reverses each contour so outlines keep their direction. A generator opts in to batches by naming the text field a batch fills (`batch`), which can depend on the design: a QR code only batches links or plain text, a puzzle only engraved text, a cupcake set none. A batch is capped at 60 lines and 2000 parts, checked after the first build so a heavy design cannot be multiplied into a slow request; the server also caps the names text and forces the mirror flag to a yes or no.

The neon-look sign is cut as one solid piece grown around the letters (holes filled, islands bridged) so nothing falls out of the acrylic, and the tube is an engraved band just outside each letter, which reads as a lit outline on the edge-lit sheet. The stencil cuts each letter through and, for each counter, removes a vertical strip through the letter's height, splitting the cut so the counter stays joined to the board; a test checks that no cut hole lies inside another.

## D111. Studio pro look: editor theme, reference point and dock rail

- The editor has its own theme preference (`editorTheme`, dark by default) so the Studio can look like Illustrator and CorelDRAW without darkening the start screen and the public pages, which stay light (D80). The head script and `ThemeSync` pick it for `/editor/…` paths, so there is no light flash when an editor opens.
- The artboard is white on every theme and objects with the black layer colour draw in near-black there: laser users judge cut lines against the material, not against the chrome. The editor greys are scoped with `:root[data-theme=dark]:has(.st-app)` so dialogs rendered outside the editor element match.
- X/Y, W/H, rotation, shear and flips all use one reference point (`refPoint`, default top-left so the numbers mean what they meant before). For one object rotation and shear are absolute (read from its matrix); for several they turn or shear the group by the typed amount.
- Workspaces moved to `hingelab-workspace-2`: the two-column toolbar, the 320 px dock and the collapsible dock are new defaults, and old stored layouts would have kept the one-column toolbar.

## D112. Pathfinder on Clipper polygons

- Boolean operations, Offset Path and the overlap tests use the Clipper library already used by the letter tools (integer units of 1/1000 mm). Curves are flattened at 0.01 mm before the operation, so results are polylines that are within 0.01 mm of the true outline — far below a laser kerf. Refitting curves afterwards would make results look like Illustrator's, but it can move corners; Simplify… is there for users who want fewer points.
- Each object counts by its own filled area (even-odd), and stacking order follows the document. Divide, Trim and Crop return a group named after the operation so the pieces can be moved together or ungrouped; one piece is returned as a plain path.
- Offset Path keeps the originals (as Illustrator and CorelDRAW's contour do) and puts each result just above its source.
- Dialogs with numbers preview through the store's `begin`/`preview`/`end`, so the preview never enters the history and OK commits exactly one step.
- Clean Up for Laser only treats exact duplicates on the same cut layer as double cuts; overlapping but different paths are left for the user.

## D113. Cutting tools on the Pathfinder geometry

- Knife, Eraser and Shape Builder reuse the Clipper helpers of the Pathfinder (D112) instead of a second geometry engine: the knife is a 2 µm strip subtracted from each area (pieces that only touch the cut stay one piece), the eraser is the stroke offset with round ends, and Shape Builder works on the Divide faces. Results are polylines within 0.01 mm, like the Pathfinder.
- The Knife only cuts closed shapes and only when the line crosses them completely, so a stray drag never changes a shape; open lines are cut with Scissors or the Eraser.
- The Eraser and Knife work on the selection when there is one and on every visible, unlocked object otherwise (Illustrator's behaviour). The Shape Builder needs a selection, because the regions come from the selected shapes.
- Magic Wand and Eyedropper use the cut layer, not colour: in HingeLab the layer is what decides how a line is cut.
- Scissors keep the clicked path's id for the first piece so layer names and history stay readable; the second piece is a new path just above it.

## D114. Arrays as plain copies

- Step and Repeat, Grid, Circular and Path arrays create ordinary copies, not a live array object: a laser job needs independent parts that can be nested, welded or deleted one by one, and plain copies keep the document model, export and pre-flight unchanged. Live repetition belongs to the Live Effects stack (Rotate Copies, Mirror) planned in the parity work.
- Grid gaps are measured edge to edge between bounding boxes, not centre to centre, because the gap is the material left between cut parts.
- The Circular Array centre is a fixed distance below the selection so the first copy stays where the user put it.
- Repeat Along Path spaces copies by arc length, so copies stay evenly spaced on curves with uneven node spacing.
- Transform Each's random mode uses a seed stored in the dialog, so the preview and the applied result are identical and Shuffle is repeatable.
- Align to Key Object uses the last-selected object (Illustrator's key object); Distribute Spacing with an exact gap keeps the first object fixed and lays the rest out from it.

## D116. Node editing, pen modes and the extra path operations

- All geometry is our own and lives in new pure modules (`pathMenu.ts`, `nodeOps.ts`, `strokes.ts`); existing geometry functions are unchanged. Areas go through the existing Clipper helpers (1 unit = 0.001 mm), so a 10 mm line stroked 2 mm wide with butt caps is exactly 20 mm².
- "auto" is a fourth node type stored on the anchor. Its handles are recomputed after every node move, insert, break, join or delete; dragging one of its handles turns it into a smooth node.
- Division maps onto our existing Divide (grouped result); Fracture is the same face split without the group. Flatten trims each shape in place by everything above it in the selection. Inset / Outset use miter joins so rectangles stay rectangles, and replace the shape in place (unlike Offset Path, which keeps the original).
- Cut Path is stroke-based: it cuts outlines into open pieces inside the same object (one undo step) and removes the cutter; curve crossings are found by chord sampling plus bisection.
- Inkscape-style keys are added only where they do not clash with ours (Intersection Ctrl+*, Exclusion Ctrl+^, Stroke to Path Ctrl+Alt+C, Inset / Outset Ctrl+( / Ctrl+)): Union (Ctrl++), Difference (Ctrl+−), Division (Ctrl+/) and Cut Path (Ctrl+Alt+/) keep our zoom, palette and help bindings, so those commands are reached from the menu, the Pathfinder panel or the palette. Node commands have Inkscape-style keys only; in the HingeLab set they live in the Nodes bar, Path ▸ Nodes and the palette.
- On a Direct Selection marquee the object selection is kept until the drag ends, so dragging across a selected path selects its nodes; a plain click on empty canvas still deselects.
- Pressure: width = brush width × pressure / 0.5 (limited to 5–200 %), so a mouse, which reports no pressure, draws the set width. Pencil smoothing 0–100 maps to a 0.25–5.25 px fit tolerance; 25 equals the previous fixed 1.5 px.
- Not done: on-canvas transform handles for a node selection, and linked / dynamic offset.

## D117. Live Effects as a per-object stack

- An object's `effects` array is applied in order to its own paths (in object coordinates) whenever its geometry is read. `nodePaths` returns the effect result and is what the canvas, bounding boxes, snapping, hit testing, booleans and copied SVG see, so any later export that reads `nodePaths` gets the effect result too; the new `nodeBasePaths` returns the original geometry and is used by node editing, so Direct Selection always edits the source path. Results are cached per object and recomputed only when the base geometry or the stack changes.
- Effects are pure functions from subpaths to subpaths with typed parameters and defaults computed from the object (for example the Rotate Copies centre and the Mirror axis start at the object's box). An effect that fails or is unknown passes its input through instead of breaking the document.
- Operations that rewrite an object's paths — Expand, Cut Path, Eraser, Split, booleans, Join Nearby Endpoints — bake the effects first, so the user gets exactly what was on screen. Node edits keep the effect stack on the converted path.
- All effect geometry is our own: fillet tangent length r / tan(θ/2) with cubic arcs of at most 45°, clamped to half of each neighbouring edge; offsets, hatch clipping and fusing go through the existing Clipper helpers. Corners only rounds corners between two straight segments; corners touching curves and open ends are left as they are.
- Living Hinge reuses the existing hinge pattern functions unchanged (the Hinge Box golden output is byte-for-byte the same) and clips the cut lines to the shape less a margin. Across-running cuts rotate the frame by 90°; slot-style edge cuts are cut flat at the zone edge rather than merged into the outline.
- Ctrl+& (Ctrl+7 on most layouts) opens Live Effects in the Inkscape-style set, so Make Clipping Mask loses its Inkscape-style key there; it keeps its HingeLab key and menu entry.
- The dock's grid column is now `minmax(0, 1fr)` so a long tab strip scrolls instead of widening the dock past its width; the panel tab is labelled "Effects".
- Not done: Pattern Along Path, Bend, Envelope, Roughen, Interpolate, Measure Segments, Taper / Power Stroke, live Boolean and effects linked to other objects. Position parameters are stored in object coordinates and shown in page coordinates only for objects that are moved but not rotated or scaled.

## D118. Clones as cached geometry; tiled clones, arrange, align, transform

- A clone stores only `source` and a `cache` of the original's geometry after its Live Effects, in the original's parent space (SVG `<use>` semantics: clone world = clone parent world · clone transform · cache). The cache is not in the clone's own parent space: that would need recomputing whenever the clone's group moved, and a moved group of clones (e.g. a tiled-clone group) would snap back. A new clone gets the identity transform as a sibling right above its original, so it sits exactly on it.
- `syncLinks` (in `lib/studio/links.ts`) refreshes the caches. A WeakMap remembers which source object each cache was built from, so unchanged originals cost nothing thanks to immer's structural sharing. Recomputed caches are compared before writing, so a sync never makes a spurious change. It runs after every edit and drag end as extra recipes inside the same undo step (`commit(..., { after: linkPasses })`), on previews, undo/redo, jump, replace and when the editor opens a document. The file reader (`file.ts`) does not sync: the start and projects pages import it, and pulling geometry, effects and the hinge library into them broke the 250 KB first-load budget; saved files carry the caches anyway. Chains (clone of a clone, clone of a group holding clones) take several passes, up to 32.
- Cycles are refused when relinking (`wouldCycle`). Any that still arrive (a pasted or hand-edited file) are broken by turning the clones in the cycle into plain paths. Deleting an original likewise turns its clones into plain paths with their last geometry (same id, transform, layer, name, effects kept live), so nothing on the sheet disappears; Undo restores the link. Pasting a clone into a project without its original gives a path.
- When a clone and its original move in the same operation, the clone would move twice, once by itself and once by following. `transformNodes` and a new `transformNodesEach` (a separate move per object) therefore undo the original's share on clones moved alongside it, including clones inside moved groups. Align, Distribute, Distribute Spacing, Transform Each, Arrange, Remove Overlaps, Exchange Positions, Transform (each separately) and Paste Size now batch their moves through `transformNodesEach`; results are unchanged for documents without clones.
- Node editing does not apply to clones (edit the original). Expand turns a clone into a plain path. Clones take Live Effects like paths, and Linked Offset = Clone + Offset effect. Ctrl+Alt+D stays Transform Again in the HingeLab set and is Linked Offset only in the alternative set; Ctrl+Shift+M likewise stays Move… and is Transform… only there. The Move dialog stays as a quick separate dialog.
- Wallpaper cells are our own choice from the standard plane-group definitions: rectangular groups use parity of row and column for mirrors, glides and 180° turns about the tile centre. Square groups use an s × s cell (larger side), with 2 × 2 cells turning about their shared corner and a diagonal mirror (P4M) or off-centre mirror (P4G). Hexagonal groups use a flat-top hexagon of side w centred on the tile's bottom centre, with 120°/60° turns and mirrors through the corners (P3M1), the edges (P31M) or both (P6M). The original counts as the first copy; at most 5000 copies; copies whose traced size is under 2 % are left out.
- Tracing reads the project's own images from local storage, downsampled to 400 px, as brightness with transparent pixels counting as white. Images are still drawn only as a hatched box on the canvas, and cloud-only assets that aren't stored locally can't be traced; colour and opacity tracing don't apply to laser cut lines.
- The Transform dialog previews what Apply would do; after Apply the preview pauses until a field changes so the applied step is not shown twice. Matrix → Edit current matrix needs one object and sets its world matrix exactly; otherwise the matrix is applied on top around the reference point.
- Align targets: first selected, key object (last selected), biggest or smallest bounding-box area, with ties going to the earlier selected object; a single object still aligns to the artboard. Remove Overlaps pushes each overlapping pair apart along the axis that needs the smaller move, half each way, repeated in selection order until settled (deterministic). Exchange Positions moves each object's bounding-box centre to the next one's. Random uses a fresh seed per click; the operation itself is seeded and repeatable.
- Paste Style gives the selection the copied object's cut layer and its Live Effects stack (new effect ids), replacing the selection's stack. Paste Size scales around the reference point; Width or Height alone keeps proportions when the W/H lock is on.

## D119. Vector fill, measure crossings, eraser modes, calligraphy, tweak, spray

- Fill Bounded Area is a vector operation, not a bitmap flood fill. Every visible, unlocked outline (paths, shapes, text, clones, world space after Live Effects) is thickened by half the gap (at least 0.005 mm) into walls; the free space is a large frame minus the walls; the piece containing the click is the face, unless it also reaches the frame corner (the click was outside every closed area). The face is grown back by the wall half-width plus Grow with mitre joins, so faces bounded by straight lines come out exact (4 crossing lines around 20 × 10 mm give 200 mm² to 1e-3). A click right on a line, or outside, makes nothing and shows a hint. With a selection only its outlines are walls; filling does not change the selection, so the scope stays the same for the next click. Shift+click unions the new face into the last fill and Alt+click subtracts it; the last fill's own outline is not a wall for those clicks. The result goes on the current cut layer (as the brief asked), so on a cut layer it is an outline that sits on the walls.
- Measure flattens all visible outlines once when the drag starts and recomputes the crossings on every move. Crossings that land on a shared vertex are counted once; closed paths are split into pieces between crossings with the wrap-around piece joined, open paths keep their end pieces. Labels narrower than about 46 screen pixels are left out so short spans stay readable. Convert to Item (control-bar button, or Enter with the Measure tool) adds a `dimension` node on a layer named "Measurements": an existing layer with that name, otherwise the highest-numbered layer from C03 up that no object uses, renamed, with output off and shown. Dimension nodes now draw their length on the canvas.
- Eraser Delete objects removes every object the brush touches: any overlap of its filled area with the brush, or any part of an open line inside it. Objects inside groups are removed individually and groups left empty are removed. It respects the selection like Cut away; Cut away (`eraseAlong`) is unchanged.
- Calligraphy keeps raw samples and builds the outline once, on release: a mass filter (the nib lags the pointer), speed in screen px/ms for thinning (full effect at 1.5 px/ms), pressure scaling (half pressure = set width), seeded tremor, and the nib angle blended between `angle` (fixation 100) and across the stroke (fixation 0). Each quad between nib positions and each rounded cap is made simple and positively wound before a Clipper nonzero union; otherwise a reversing stroke or turning nib would cancel itself. The union is simplified, with smooth nodes where the outline bends under 35° and corners elsewhere. The live preview is the unmerged ribbon (cheap). Output goes on the current layer if it is a fill (engrave) layer, otherwise on the first fill layer (C00).
- Tweak works on the selection when there is one, otherwise on everything visible and unlocked under the brush. Object modes act on top-level objects whose bounding-box centre is in the brush; path modes act on paths, shapes and text (shapes and text become paths, Live Effects stay live; clones are left alone). The brush weight is (1 − (d/r)²)², times force. Before moving nodes, segments that pass within 1.2 radii of the brush and are longer than radius × (0.05 + 0.6 × (1 − fidelity)) are split without changing the curve (cap 4000 nodes per path). A drag accumulates on a working copy and is committed as one "Tweak" step.
- Spray needs a selection (the sources stay selected so strokes can repeat). It places `amount` items per step, one step on press and then one per quarter radius of pointer travel (at least 0.5 mm), so the count does not depend on mouse event rate. Distance from the brush centre is radius × u^(0.5 + 2.5 × focus). Each stroke's randomness is seeded from Seed and the stroke number, so results are reproducible but strokes differ. No overlap tests the item's bounding box (padded by the gap) first, then grows the item's outline by the gap and rejects it if Clipper finds any intersection with an earlier item or any visible object; up to 6 tries per item, so a full area yields fewer items rather than overlaps. Single path unions all items of a stroke into one path above the first source. The whole stroke is one undo step.
- Shortcuts for the new tools exist only in the alternative (Inkscape-style) set: U / Shift+F7, C / Ctrl+F6, W / Shift+F2, A / Shift+F3; in the HingeLab, CorelDRAW and LightBurn sets they are reached from the toolbar and the command palette (keywords such as 'paint bucket', 'live paint', 'ruler', 'rubber', 'nib', 'scatter').

## D120. More Live Effects, effect handles and linked effects

- Linked effects (Pattern Along Path, Interpolate, Live Boolean) store `link` (the other object's id), `linkCache` (a copy of its geometry) and `linkError` in their parameters. `syncLinks` fills the cache in the same passes and undo step as clones, so `nodePaths` stays pure and an effect never reads the document. Caches are identity-checked so unchanged links cost nothing. Pattern Along Path reads its pattern in page space, so rotating or scaling the pattern object counts. Interpolate and Live Boolean read the other object in the carrier's own coordinates, so it stays where it is on the page when either one moves.
- If the linked object is deleted, the effect passes its input through and shows "deleted" in the panel (`linkError: "missing"`). If a link would make a loop (A reads B while B reads A, also through clones), linking is refused; a loop made by hand turns those links off (`"cycle"`) instead of recursing. Reset keeps the link. Unlink drops it.
- With two objects selected, the panel and the palette commands put the effect on the bottom object and link the top one. "Use copied object" links the clipboard object if it still exists in the document. Live Boolean hides its operand when linked; the "Hide operand" checkbox toggles that object's own Hidden flag, so a hidden operand is neither drawn nor cut.
- Effect handles are a generic part of the registry: `handles(params, input)` gives points in object coordinates, `drag(params, index, at, input)` gives a parameter patch, and `outline` gives the dashed guide drawn with them. The panel publishes which open cards have handles (`fxHandles` in the editor store), and the canvas draws and hit-tests them first under the Selection and Direct Selection tools. A drag uses begin / preview / end, always computed from the document before the drag, so it is one undo step and Escape cancels it.
- Measure Segments leaves the geometry unchanged. Its labels come from a separate `guides` hook on page coordinates (so lengths include the object's scale), drawn by the canvas only. `nodePaths`, booleans, preflight, copied SVG and exports never see them, and Expand keeps the path and drops the labels. This was chosen over output text because a laser file must never contain annotations by accident.
- Taper and Power Stroke reuse `brushOutline` from the stroke tools unchanged. Bend and Envelope densify curves before warping (perspective warps flattened polylines; straight lines stay straight). Roughen uses a seeded mulberry32 generator, so the same seed always gives the same outline. Interpolate resamples both outlines by arc length after matching orientation and start point. The Hinge Box golden output is unchanged.
- Limits: the Bend guide has two nodes (no adding nodes); Interpolate blends along straight lines (no trajectory path); Power Stroke handles sit on the first subpath; Pattern Along Path uses one pattern object (its subpaths together) per spine subpath; Measure Segments labels use the document unit and a fixed blue guide colour.

## D121. Trace Bitmap, document grids and the structure inspector

- Trace Bitmap is written from scratch: threshold, Sobel and seeded k-means bitmaps, pixel-edge contours (left turn at diagonal saddles so diagonally touching pixels join), staircase smoothing, simplification within a pixel tolerance and corner-aware Bézier fitting; centre-lines come from Zhang–Suen thinning with spur pruning. No potrace (GPL) and no other tracing library, so no new dependency and no licence risk.
- Tracing runs in a Web Worker (centre-line and colour modes take up to ~0.8 s on a busy 1000 px image); a newer preview request supersedes older ones, and an inline fallback runs when workers are unavailable.
- The trace keeps the image's transform and sits just above it, so it lines up whatever the image's scale or rotation; centre-line output is open lines, everything else closed areas.
- New grid types and the sheet background are optional document fields: no schema version bump, older documents open unchanged, and a rectangular grid stores exactly what it stored before. Rectangular snapping and drawing are untouched; the other kinds snap through new functions (`snapMoveGrid`, `snapPointGrid`) that let objects, guides and smart guides win first. Modular grids snap box edges per axis; axonometric and polar grids move the nearest corner or centre onto a grid node.
- No user scale: every length in a document is real millimetres and exports must keep physical size, so a user scale would either change geometry or make exports disagree with the screen. Display units already cover the need to work in other units.
- The sheet background is a screen-only preview (CSS gradients of our own); it is never cut, engraved or exported.
- The Structure Inspector is read-only on purpose: edits stay in tools, panels and dialogs, which keep undo and validation in one place. Geometry and caches are shown as sizes, not dumped.
- Pre-flight warns but never blocks, and only about the operation's own results: open paths (not after Cut Path or centre-line tracing, whose results are meant to be open) and lines lying on other lines (the laser would cut them twice). Engraved traces are not checked because filled areas may share edges. Fill Bounded Area is not checked: its result deliberately follows existing outlines.
- Escape in a modal dialog now closes the dialog instead of clearing the selection behind it (the canvas key handler ignores events from dialogs).
- Extensions are a design only (docs/EXTENSIONS.md): JavaScript in a sandboxed Web Worker with a versioned message API, declared permission scopes, signed packages and no Python.

## D122. Parity 7b: snapping controls, view transform, selection extras, swatch bar, shortcut set

- **Snapping is opt-in per target, stored as optional fields.** `doc.snapping` gains `enabled`, `mode` and twelve target toggles (`SnapToggles`). An absent field means its default, and the defaults reproduce the old behaviour exactly: same targets, same line order, same node order. Old documents and the golden tests are unaffected. With the master switch off, every snap function returns the raw point. Path intersections come from a sweep over flattened outlines, capped at 3000 segments, skipping adjacent segments of the same outline. Text baseline snaps to the text origin and, when unrotated, to the baseline line.
- **One view transform.** `View` is `{zoom, x, y, rotation?, flipX?, flipY?}`, with screen = R·F·(zoom·p) + (x, y); positive rotation turns clockwise on screen. All screen↔document conversion, hit-testing, handles, cursors, marquee, zoom drag and the text editor go through `viewTransform.ts`. Upright and unflipped, the SVG output is byte-identical to before. While the view is turned, the rulers are hidden on purpose: a turned ruler would need rotated tick axes. The marquee uses the screen rectangle mapped to a document quadrilateral, with the same touch rule as unrotated. Ctrl+Shift+scroll turns by the snap angle once per wheel notch (small trackpad deltas accumulate), and Ctrl+scroll still zooms.
- **Zoom history is per session, not per document.** It keeps 50 entries. A burst of wheel zooming records one entry, and fit and zoom commands record one each. Previous Zoom and Next Zoom have keys only in the Inkscape-style set (` and Shift+`).
- **Split view and outline overlay are display-only.** The outline half is a clipped, non-interactive copy, so the pointer always acts on the real objects at identical positions. The divider position lives in UI state.
- **Selection.** Alt+click without moving selects the next object down at that point, cycling through the stack. Alt+drag on an object still duplicates it, as before. Alt+drag on empty canvas is touch selection with a 2-screen-pixel tolerance.
- **Rotation centre.** It is kept per selection, keyed by the selected ids, and is not saved in the file. It follows the selection when it is moved or nudged. The Rotate tool rotates around it, and the Transform dialog uses it when the reference point is the centre. Double-click resets it.
- **Snap angle preference** (1–90°, default 15°): Shift snaps to it for rotate and shear. Line, Pen, Knife and Measure keep Shift = 45° and use Ctrl+Shift = snap angle. The [ and ] node-rotation keys and View → Rotate also use it. A selection-cue preference was not added: the selection outline is the only cue and needed no variants.
- **Swatch bar replaces the fill / stroke split.** A laser layer has one colour, so Shift+click selects that layer's objects instead of setting a stroke. Edit Layer… opens the Cut Layers panel with that layer current. The bar is a workspace setting (on in Essentials, Laser and Typography; off in Minimal), its grid row collapses when hidden, and presentation mode hides it.
- **Commands bar skipped.** Its buttons (new, open, save, import, export, undo, zoom, group, align, and so on) already live in the menu bar, the control bar, the tool footer and the command palette. A fourth copy would cost a toolbar row on every workspace for no new capability.
- **Shortcut set.** About 70 keys from the public keyboard reference are mapped onto existing commands, using `[]` to drop a default where it would clash. `conflicts()` is empty for all four sets. New commands were added only for real view features (rotate, flip, zoom presets and history, split view, outline overlay, snapping, swatch bar), never just to match a key. Palette search keywords cover familiar names, and tools are shown as "Tool: …" in the palette. "Inkscape" appears only in the set's existing label and in search keywords.

## D123. Parity 7c: text on path, flowed text, manual kerning, vertical text, connectors

- **One text node, new optional fields.** `TextNode` gains `onPath` / `pathStart` (% of the path length) / `pathSide`, `flowInto`, `frame`, `vertical`, and `kerns` / `shifts` / `rotations`. Text without them is laid out by exactly the same code path as before, and the point and area results are unchanged: existing tests are untouched, and outlines were compared byte for byte over 864 point and area cases.
- **Linked frames, synced like clones.** Text on a path and flowed text keep a copy of the source's outline in the text's own coordinates (`frame`), refreshed by the link sync in `links.ts` whenever the source or the text's transform changes, after every edit, preview, undo and redo. The frame is the layout's input, so moving only the text snaps it back onto its path, the same as the other linked objects (D120). A deleted source leaves the text where it was with the last frame. Put on Path and Flow into Shape refuse links that would make a loop, and a loop that is made anyway is skipped and keeps the old frame.
- **Text on a path.** One line: line breaks become spaces. Each glyph's baseline midpoint is placed at its distance along the path and the glyph is turned to the tangent there, which is SVG text-on-path placement. Closed paths wrap round, and on open paths whatever runs past either end is hidden and reported as overflow. Right-to-left text is placed in visual order, so it reads correctly. On an open path it starts at 100% by default, so it ends where the path ends. Remove from Path places the point text at the start point.
- **Flowed text.** Each line band (ascender to descender) is cut into the spans the shape covers over the whole band height (scanline over the flattened outline), so letters never poke out at curves. Words fill the spans in reading order, right to left for RTL paragraphs. A word wider than its span is placed only when the span is at least half the frame wide, as area text puts a long word on its own line; otherwise the span is skipped. Each paragraph starts on a new band, and text that does not fit is cut and marked as overflow. A 40 × 20 mm rectangle wraps exactly like 40 mm area text. Unflow gives area text of the frame's width with the same first baseline.
- **Manual kerning units.** `kerns[i]` is extra space before character i, and `shifts[i]` is the baseline shift (positive is up); both are in 1/1000 em, like tracking. `rotations[i]` is in degrees clockwise, wrapped to (−180, 180]. They are keyed by character index and remapped by common prefix and suffix as the text is edited, so they stay on the same letters. One Alt+arrow step is one screen pixel at the current zoom, Shift gives ten, and rotation steps by the snap angle. Values are rounded to 0.1 and zeros are dropped. The Alt keys exist only inside the text editor, so they never clash with canvas shortcuts. Ctrl+Z while typing is the text box's own undo. After Escape it undoes kerning in the document history, where repeated Alt-key steps on one text merge into one undo step.
- **Vertical text.** Characters run top to bottom and paragraphs become columns from right to left, one line height apart. HarfBuzz vertical shaping advances are used when the font has vertical metrics (`vmtx`), otherwise the font's line height. Latin letters stay upright: there is no sideways rotation of Latin runs.
- **Editing non-plain text.** Text on a path, flowed, vertical or manually kerned text is edited in a floating box under the object, while the canvas shows the live result with the kern markers. Plain text keeps the in-place editor. Outlines are computed after a drag ends, as for all text.
- **Connectors are paths with a `connector` field** `{from, to, mode}`. The route starts at both objects' bounding-box centres, and the first and last segments are cut where they cross each object's outline (falling back to the box). Right-angled mode uses simple L and Z routes: a vertical–horizontal–vertical Z when the boxes overlap horizontally, horizontal–vertical–horizontal when they overlap vertically, an L otherwise, and a straight line when the boxes overlap both ways or the centres line up within 0.001 mm. It is not obstacle-avoiding routing. The route is recomputed in the link sync into the connector's own coordinates, so moving the connector alone does not detach it. Deleting either end, connecting an object to itself, or a link loop turns the connector into a plain path, and Expand does the same on purpose. The Connector tool never attaches to another connector.

## D124. The design folder is catalogued, not copied

- HingeLab is public, so bundling a file redistributes it. A design is bundled only with positive evidence that redistribution is allowed: the owner's own work, public domain/CC0, CC BY with attribution, or an explicit licence. Missing licence plus third-party origin (catalogue ids, shop SKUs, VK reposts, clip-art CDs, trademarks) means excluded.
- Non-commercial licences (CC BY-NC-SA) are excluded because HingeLab sells Pro plans. Share-alike (CC BY-SA) is excluded by default to keep the bundled library free of copyleft, in the spirit of CURSOR_INKSCAPE_PARITY.md §0; it can be opted in per file.
- Result: 2 designs (5 SVGs) bundled; the Ceramic Frame is assumed to be the owner's work and is listed for confirmation.
- Excluded files remain usable privately through Studio's SVG import, which keeps them on the user's device.
- The scan is read-only: zip central directories are parsed directly (zip64 aware, CP866 names), nested zips are inflated in memory, and nothing is written to the source folder. The scripts stay in tmp/ (not shipped); the catalogue is the committed record.

## D125. SVG import reads numbers, never markup

- The importer is our own small XML reader plus a geometry converter (`lib/studio/svgImport.ts`); no DOMParser, so it runs the same in tests, in the editor and in build scripts. Only coordinates, colours (as layer numbers) and names cleaned to letters, digits and a few punctuation marks reach the document. Scripts, event handlers, foreignObject, images, external references and CSS url() never get through, and nothing from the file is ever inserted as HTML.
- DOCTYPE entities expand once, are at most 512 characters, and share a 4 MB budget (no entity bombs). Element count (250,000), objects (20,000) and anchors (600,000) are capped; a larger drawing imports its first part with a warning. Files over 40 MB are refused.
- Illustrator writes px as points: the importer detects Illustrator files and reads them at 72 per inch. Checked on the archive: the KV-1 sheets are 850.394 px tall, exactly 300 mm at 72 per inch.
- Black strokes go to a cut layer, not C00, because C00 is the engrave-fill layer and laser files almost always mean black lines as cuts. Fills engrave on C00.
- `svgDocument` builds a whole project from one or more SVGs, one sheet per drawing. Both Import SVG and the bundled design templates use it.
- Checked on 48 real files from the archive (CorelDRAW, Illustrator, Inkscape, xTool, up to 22 MB): no failures, and all but the 22 MB file import in under 0.1 s.

## D126. Template library: three kinds of template, one gallery

- **Studio templates** (`lib/templates/studio.ts`) are built from Studio's own shape primitives and Live Effects (living hinge, rotate copies, hatches) when opened, so the user edits a rosette's count or a hinge's spacing rather than flattened paths. They are code, not files: nothing is downloaded but the thumbnail, and the geometry engines are untouched (only their public parameters are used).
- **Bundled SVG templates** are clean cut files in `public/templates/files/<id>/`, one per sheet, opened through the same importer as Import SVG (D125). The build writes them in mm with LightBurn's colours for HingeLab's four working layers only (black fill engrave, blue score, red cut, green inner cuts), no metadata, numbers to 0.01 mm. Generator templates are built from their settings with the generators' own code; the imported designs are re-exported from what the importer read.
- **Editor templates** open only in their classic editor (“Customise in …”): every Hinge Box design (Hinge Box exports carry the Free plan's watermark, so bundling their cut files would bypass it) and any generator design whose export needs Pro. The gallery marks them Pro when the plan rules say so. Classic editors read `?p=<product>&template=<id>` and apply the settings as one undoable step, like `?preset=`.
- Thumbnails are drawn at build time (assembled 3D-style views for generator and Hinge Box templates, a flat plywood view for the rest) on a 1/600 grid with relative whole-number steps, so every one is under 64 kB; the gallery shows them as `<img>` and lazy-loads them. The catalogue metadata is about 25 kB; the Studio template code and the importer load only when a template is opened.
- Licensing (D124) decides what is bundled: two designs from the collection qualified. The CC BY credit (title, author, source, licence, changes) is shown in the detail view, written as a comment in each file, and listed in `public/templates/LICENSES.md`.

## D127. Procedural reliefs for the design library

- Every new model is built in code from height functions (Gaussian features, splines, seeded value noise and an exact Euclidean distance field for puffy outlines), so there is no third-party model or image and no licence question. Each is a closed, outward-facing mesh under 100k triangles and builds in under 25 ms.
- Rectangular reliefs are closed height fields with a low base (about 1.2 mm). Under the parallel method with backboard slats and empty slots filled, a base lower than the slat depth turns into plain slats wherever the picture is flat. That is what makes the slat-portrait look: fins carry the face, plain slats fill the rest of the board.
- Shaped reliefs (face, heart, star, flowers, moon) are polar height fields whose outline comes from scanning for the outermost crossing, so the plate under the fins follows the shape.
- The new models live in their own module with their own small mesh builder rather than inside `library.ts`, so the existing library shapes and their snapshot tests are byte-for-byte unchanged. `WALL_RELIEF_IDS` decides which of them sit on the wall (flat back at z = 0) and `RELIEF_IDS` extends the server's list of allowed library ids.

## D128. Categories and stored part counts for parametric presets

- Presets gain a required `category` and optional `tags` (extra search words) and `finish` (the 3D view's look) through a `ParametricPreset` type that extends the shared `Preset`. Old saved designs and preset ids are unchanged; the 14 existing presets keep their ids and settings and only gain a category.
- The Pro badge uses the existing `parametricLocks` rule with the part count. Part counts are only known after slicing, so `scripts/build-preset-thumbs.mjs` now also writes `lib/parametric/presetParts.ts` while it slices each preset for its thumbnail; the build test fails with a hint to rerun the script when a count goes stale. Several wave presets that the Free plan cannot export (more than 30 parts) now show the badge they should have had.
- Reliefs whose base is thinner than the minimum feature fall apart into many small pieces on a shaped plate, so those presets use backboard slats (each fin is joined to its slat), which keeps parts whole and gives the slat-wall look.
- Radial formula presets use 30 fins so fins never collide at the 20 mm hub.

## D129. Design generator writes ordinary parameters

- A generated design is a recipe, a few knob values, a seed and a “cut as” choice. `designParams` turns it into ordinary parametric parameters (a formula source, a method and settings), so saving, undo, sharing, the plan rule and export treat it like any hand-made design; nothing new is stored.
- The same recipe, knobs, seed and cut always give the same parameters (seeded mulberry32 with a hashed seed so consecutive seeds look different). A test builds every recipe with every cut plus 120 random designs and checks each against `parametricRequestError`, and slices the defaults within the limits.
- Previews and the six variations are drawn from the formula on a coarse grid (hillshade plus the fin lines) instead of slicing, so changing a slider is instant; the full model is sliced only when the design is used. Library and text sources are not previewed this way; the gallery uses their stored thumbnails.
- Clock recipes are written with the shape specs so the dock's shape buttons recognise them. Radial recipes use a 20 mm hub and at most 30 fins so fins never collide at the hub.
- Formula sources stay Pro, so generated designs show the Pro badge on Free; the generator is still free to explore.
- The Look (wood, dark, white) only changes the 3D view colours and is remembered locally; it is not part of the design file. Presets may suggest one (the flagship opens dark).
- The start screen ships the preset list in the editor shell, so presets must not import heavy modules. Clock and frame presets keep their shape specs plus the literal formulas `shapeExpression` writes (a test checks they match and are recognised), which keeps `shapes.ts` out of the shell and the shell inside its 150 KB budget.

## D130. Rail pictures are rendered at build time from the real engines

- `scripts/rail-art.ts` renders each card with the same code the editors use (`sceneSVG` for hinge boxes, `lettersThumbSVG`, `partsThumbSVG` for parametric parts, `assembledSVG` for generators) and writes static SVG files to `public/rail/`. The pictures always match what the option makes, and no rendering happens in the browser.
- The bundle carries only a compact list of groups and values that have pictures, plus one version hash (`lib/railArt.generated.ts`, about 4 KB), not a URL per card. `railPic` in `lib/railArt.ts` builds the URL. This keeps the Editor shell + Hinge Box bundle within its 150 KB budget.
- A group whose options all render alike keeps its line drawing (or uses extruded tokens of that drawing for generators), so a card never shows a picture that does not tell the options apart. An option that fails to build falls back to its token.
- `GalleryGroup.pics` names the picture group when it differs from the line-art key (Letters walls and lids, generator choices keyed by field), so the existing `art` keys and accessible names stay unchanged.

## D131. Letters base rim

The Letters base and lid were the outer wall face exactly, and the tab slots are centred on the wall, so each slot's outer side lay on the plate edge with almost no material. A Base rim parameter (mm, default 0) offsets the base and lid plates outward by the rim before the slots are cut, which moves the slots in from the edge. It defaults to 0 so stored designs and tested geometry do not change, and it lives in Letters only: the Hinge Box geometry is golden-tested and was left untouched. Counters shrink by the rim as well, which is the same offset seen from inside; the removable-lid lip still fits inside the walls, so it is not offset.

## D132. The desktop 3D view draws a scene the server builds

- The desktop must not carry the geometry engines, so it cannot build the 3D scene itself. When a generate request has `model: true`, the server builds the same three.js scene the website uses (`generatorScene` or `buildHingeScene`) twice, assembled and exploded, and serializes it as a `D3Model` (`lib/desktop/model3d.ts`): extruded outlines (`slab`), indexed meshes (`mesh`) and line sets (`lines`), each with a matrix and an explode offset taken from the difference between the two builds. Parts that exist only in the assembled build fade out when exploded. The desktop rebuilds these objects (`desktop/src/scene3d.ts`) and applies the shared look from `lib/three/looks.ts`, which holds rendering only.
- The model is optional and only sent while the 3D view is open, so the 2D sheet's response and speed do not change. A model over 600,000 numbers is dropped and the view says the design is too large to show in 3D; a model that fails to build never fails the SVG.
- One WebGL canvas draws all four views with a scissor rectangle per view, instead of four canvases, to stay within WebGL context limits and share one scene. Each view has its own camera and controls on a transparent overlay, so the view label and the view cube stay clickable.
- The 3D code is a lazily loaded chunk (about 155 kB gzipped), so opening the app and the 2D sheet do not load three.js.

## D133. 3D dimensions measure the solid parts and read kerf as the whole millimetre

- The sizes are measured from the 3D model actually shown, not from the form fields, so one piece of code (`lib/three/dims.ts`) serves the Hinge Box, Letters, every generator and the desktop app, and laid-flat parts are measured too. Only meshes count: hinge slits drawn just off the wall surface, the cut lines painted over parts lying flat, and the 0.2 mm engraving skin (marked `userData.noMeasure`, carried to the desktop as `noMeasure` on the slab) would otherwise add a fraction of a millimetre.
- Cut outlines are grown by half the kerf and curves are faceted, so a 140 mm Hinge Box base measures 140.15 mm and a 300 mm round clock 299.9 mm as modelled. A size within 0.2 mm of a whole millimetre is therefore shown as that millimetre (140.0 mm, 300.0 mm); anything else is shown to 0.1 mm. This is display only; no geometry changes.
- Each axis is drawn along the bounding-box edge that lies furthest out on screen and set off past the whole outline, so the line never crosses the model; an axis seen end-on (shorter than 28 px) is left out. The lines are an SVG overlay redrawn with every frame, not 3D objects, so they stay crisp and readable at any zoom.
- They are hidden while exploded because an exploded model is not the product's size.

## D134. No wireframe display in the desktop 3D views

The wireframe mode drew every triangle of the extruded parts, which on curved outlines and lettering is a dense mesh that says little about the design, and the Edges mode already shows the parts' outlines over the shaded model. The mode is removed rather than hidden: `Shade3D` is `"shaded" | "edges"`, and the stored preference is read back as Shaded when it holds anything else, so 1.0.9 settings carry over. The website's 3D view never had it.

## D135. One 3D workspace for the website and the desktop app

The desktop app had a four-view workspace (orthographic Top, Front and Left plus Perspective, view cube, Shaded / Edges, dimensions per view) while the website showed a single perspective view with its own floating controls, so the same design looked and behaved differently depending on where it was opened. The workspace is now one component, `lib/three/QuadView.tsx`, used by the desktop `View3D` and by every 3D view on the website; scene building stays where it was (each product's own builders, the desktop model loader and the parametric viewport), so no geometry changed. Models are passed as `{group, dispose, explode?}`: web scenes are rebuilt when the explode amount changes, the desktop model explodes in place, and the parametric viewport keeps one root group whose layers are swapped and calls `refresh()`. On the website the toolbar is portaled from the lazily loaded 3D chunk into the Sheets / 3D bar rather than built into the editor shell, which keeps the editor within its 150 KB budget; layout, shading and dimension choices are remembered in the browser.

## D136. AI designer: the model chooses settings, the products make the geometry

The AI designer turns a description or a photo into a design, but the model never draws: it picks one product and preset from a menu built from the products' own field definitions (`desktopCatalog()` for the Hinge Box and generators, a short curated list for Letters, presets only for Parametric), then returns `{key, value}` pairs for the listed fields. Each value goes through the same checks as a typed one (`coerce`, `sanitizeGeneratorParams`, `parseLetterRequest`, `parametricRequestError`) and the cut file comes from `generateDesign` with the caller's plan, so unknown keys and out-of-range values are dropped or clamped and reported, Pro designs stay locked on Free, and every slot, hinge and joint is the tested geometry. Outline (path) fields and machine settings are kept out of the menu. The model is reached only from the server through the Vercel AI Gateway (OIDC on Vercel, no key in any client), with a fallback list of models; on the current free gateway tier only `openai/gpt-5-mini` answers, and the faster first choices start working when the team adds credits. Requests are signed in, size-limited and rate-limited per user (burst and daily, by plan). Letters and Parametric have no desktop editor, so their result carries a short link that the website's `/app/ai` page turns into the editor handoff; it holds only the settings that differ from the preset and stays under 380 characters so it fits the desktop website view's 512-character limit even inside its one-time sign-in link, whose `next` now keeps the fragment.

A Parametric design from a photo used the chosen preset's own source model, so the user's photo only steered which preset was picked. ## D138. The AI designer can use the owner's OpenAI key

The gateway's free tier only allows gpt-5-mini, and a ChatGPT subscription cannot be used by a server: OpenAI only grants programmatic access through API keys. ## D139. The note about a photo is its own field

People describe a photo differently from a product they want: they correct it ("the real one is 30 × 40 cm"), change it ("my name instead of the face") or say which part matters. Mixing that into the main description loses whether it refers to the photo. A separate `imageNote` field, only kept with a photo and labelled for the model, lets the prompt say plainly that the user's words beat the model's reading of the picture, and keeps the main box for describing a product without a photo.

## D140. Editing an AI design sends the design back, not a conversation

An edit could have been a chat thread the server keeps, but the design itself already says everything needed and the server is stateless. So the client sends the design's settings with the change; the server treats them like any other client settings (merged and sanitized by the product, never trusted), skips the product pick so an edit cannot turn a sign into a box, and tells the model the current result's size because sizes such as a word's width follow from other settings. Undo is kept on the client as the list of earlier designs.

## D141. The AI designer draws flat designs itself, and checks its drawing with measurements

Filling in a product's preset made every sign, stand or keychain look like the site's templates, and anything the presets could not do (a round phone stand) came back as the nearest template. Engineered products (box joints, living hinges, slices, puzzle cuts) stay with the tested generators, because a model cannot draw those reliably; flat artwork is what a strong model draws well. The model writes only path data and text boxes, never SVG markup, so the server builds the file itself, outlines text with its own fonts and runs the same inert-markup check as every other file. A model looking at a picture misses facts it cannot see, so the server measures them (engraved share, cuts that would drop out with their engraving, open cuts) and states them with the picture. The engrave layer is one even-odd path because that is how LightBurn fills it; text is unioned first so joined letters keep no seams. True training (fine-tuning) is not part of this: the knowledge is a laser-design handbook in the prompt plus the draw, look and fix loop.

## D142. AI designer: modern page design

The AI page was a plain form. It now reads as the product's front door: one composer card holds everything the user types or drops (a photo can be dropped or pasted anywhere on it), so the page has one obvious place to start. ## D143. AI designer: example library

The owner asked how to teach the designer with product photos. Fine-tuning needs hundreds of clean request-to-file pairs and is redone for every new model, so the designer learns in context instead: examples of the shop's finished products are shown with the request.

- **What an example is.** The cut file and, optionally, a photo of the real product, with a title, a description and tags. Photos alone teach what looks good but not how to draw it for the laser; the pair teaches both.
- **Safety.** The uploaded SVG is never stored or shown as uploaded: `importSvg` reads only geometry and colours, and the server redraws it in mm (fills black for engraving, strokes in their LightBurn layer colour) before it renders a PNG with resvg. Photos must be JPEG data URLs under the AI photo limit. Tables are in the private schema and files in a private bucket with no policies; the server reaches them with the service role through functions that check the curator again. Pages and routes answer 404 to anyone who is not a curator. Images are served through our own route because the site's CSP does not allow Supabase image URLs.
- **Who curates.** The owner's account by its confirmed email, written into `ai_is_curator`, so it works even if the account is created after the migration; more curators go into `private.ai_curators`.
- **Which examples.** Up to two, scored by shared words with the request, the photo note and the planner's name and brief (title and tag words count double; common words such as laser, cut and plywood are ignored). Nothing is shown when nothing clearly fits, so unrelated examples cannot pull a design off course.
- **Where.** Only the first drawing call of a new original design (web and desktop routes). Reviews and edits judge the request alone. The list is cached for five minutes per server, and loading is capped at six seconds; any failure means the design is drawn without examples.
- **Limits.** 500 examples, SVG up to 2.5 MB, the whole upload under the host's 4.5 MB request limit.

## D144. AI designer: the shop's project archive as examples

The owner asked to import 1000 files from `D:\Archive\Print\SVG Files` with titles.

- **What was taken.** The folder's SVGs were mostly not laser work: 188 coloured cartoon faces and vehicles and 411 sheets of colour clipart (one folder a copy of another). Redrawn for the laser they become solid black blobs, which would teach the designer the very failure it is told to avoid (large engraved areas), and some show real people and team logos. They were left out. The useful part is `Prefabricated`: 2928 finished laser projects, most with a photo of the real product, whose cut files are DXF or CorelDraw. 1244 had a photo and a DXF or SVG that converts cleanly; 1000 of them were picked, balanced across the 30 categories (at most 68 per category), skipping drawings heavier than 700 KB once redrawn.
- **DXF reader.** `lib/ai/dxfRead.ts`, written from the DXF reference (clean room): lines, arcs, circles, ellipses, LWPOLYLINE and POLYLINE with bulges, NURBS splines by de Boor, block inserts with scale and rotation, mirrored entities (extrusion z < 0). Text, hatches, images, dimensions and paper space are left out. ## D152. CorelDRAW tools and commands

- **3-point shapes (`lib/studio/drawTools.ts`).** The base line gives length and angle; the third point's signed distance from it gives the height. Rectangles and ellipses stay live shapes, placed by a rotated transform. A click on the base line makes a square or circle. The curve is the quadratic through the third point, stored as a cubic.
- **Smart Drawing.** Our own recogniser: closed test from the end gap, corners by Douglas–Peucker plus merging small turns, a straightness check against the polygon, an ellipse fit from principal axes and a rectangle test on corner angles. - **Crop and Virtual Segment Delete (`toolOps.ts`).** Crop intersects areas and clips open lines with Clipper, deletes what is wholly outside and leaves what is wholly inside untouched; images are not cropped. Straight segments are split linearly, since their parameter is linear.
- **Contour and Boundary (`pathfinder.ts`).** Contour repeats the existing Offset at multiples of the spacing (outside, inside, or inwards until nothing is left), capped at 200 steps. Boundary is the union of the closed areas, outer rings only, added above the selection.

- **Distort live effect (`effects/distort.ts`).** Push & Pull scales nodes and handles in opposite directions about the centre; Zipper offsets alternate points along the normal (optionally random, seeded, or smoothed into waves); Twister rotates densified points by an angle proportional to their distance from the centre. ## D153. AI designer: black-and-white pictures traced with a pad

The owner asked that every black-and-white picture given to the AI designer come back with a vector pad round it. Asking the model to redraw such a picture loses its exact shapes, so these pictures are traced instead (`lib/ai/padTrace.ts`, server only).

- **Detection.** The photo is decoded on the server with resvg (embedded in an SVG `<image>`, system fonts off) at its own proportions, at most 1024 px. It counts as black-and-white when at least 97 % of pixels are grey (chroma under 40), at least 90 % are near black or near white, and the smaller of ink and background is at least 0.2 % (so a blank picture does not count). Anything else, and every revise of a normal design, goes through the existing pick.
- **Tracing.** The brightness is blurred slightly (Gaussian, 0.9 px) to remove JPEG noise along the edges, enlarged three times (bilinear, at most 3072 px) and cut at 128, so edges fall between the picture's pixels instead of following its noise. When most of the border is dark the picture is inverted, so a light figure on a dark ground traces the figure. Specks under 0.001 % of the picture are dropped, then the existing Studio tracer (`traceOutlines`) makes the outlines, simplified at half a picture pixel with corners sharper than about 40° kept as corners. Tracing the 1024 px pixels directly left the JPEG noise in as wavy edges and bowed straight lines.
- **Pad.** Separate parts (a figure and its name) are joined first by a closing (grow then shrink, doubling the gap until one outer ring remains, else the convex hull). The pad is that outline offset by the border with round joins (Clipper, the Studio's own helpers). The artwork is scaled so the finished piece's longest side is the chosen size, corrected for the border in up to three steps. A hanging hole of 4.5 mm is placed above the highest ink point near the middle, with a round tab added to the pad so it always sits inside the piece.
- **Model.** One low-effort call names the piece and returns size, border, hole, material and thickness under fixed rules (keychain 40–60 mm, coaster 90–100, sign 150–400, otherwise 100; border about twice the thickness, 3–8 mm). Values are clamped. If the call fails the defaults are used (100 mm, 4 mm border, 3 mm birch plywood), so tracing never depends on the model.
- **Result.** The design is an `art` design (cut and engrave layers, opened in Studio like other art) with `params.pad` keeping the spec. Too detailed pictures are simplified in steps until the file is under 140 000 characters, else a clear error. Revise of a traced piece changes only size, border, hole and material and rebuilds from the stored engraving; other requests get a note to open it in Studio.
- **Not done.** Grey photos are not posterised into a pad; WebP decoding is untested (both apps send JPEG). No generator or hinge math changed. The Hinge Box golden test is unchanged.
